2. **Composed verdict semantics (THE load-bearing semantic interaction — 081 × 082 MUST compose coherently).** CR-081 says "a red test turned green = full PASS."    - **(a)** Does the story declare a `deferred_verification` entry that was NOT run in this QA pass? → `PASS-PENDING-SMOKE` (082 wins; the deferred heavy check is still owed; close gate enforces it).
   - **(b)** Else, are all Gherkin scenarios covered by passing tests — INCLUDING red-now-green tests counting as their own green (081)? → full `PASS`.
   - **(c)** Else → `FAIL`.
   The key non-contradiction: 081's "red-now-green = PASS" applies to the STATIC scenarios; 082's PASS-PENDING-SMOKE is gated on an UNRUN DEFERRED scenario, a different axis. A story can be red-now-green on its static scenarios AND still be PASS-PENDING-SMOKE because a separate heavy scenario is deferred. **CR-082's Developer MUST write the verdict region so the deferred-check (082, step a) is evaluated BEFORE the full-PASS branch (081, step b)** — i.e. PASS-PENDING-SMOKE shadows PASS when a deferred entry is unrun. The composed output line: `QA: PASS | PASS-PENDING-SMOKE | FAIL`. A Developer working only on 082 might overwrite 081's red-now-green clause when editing the nearby verdict line — flag: the two clauses live in adjacent-but-distinct subsections; preserve 081's Workflow-step-4 clause verbatim.
