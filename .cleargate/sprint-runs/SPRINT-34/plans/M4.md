  ```
  export function resolveDefaultPayloadDir(): string {
    const thisFile = fileURLToPath(import.meta.url);
    const pkgRoot = path.resolve(path.dirname(thisFile), '..');   // dist/cli.js → dirname=dist/ → up one = PACKAGE ROOT

  }
  ```
  In the published package the bin is `dist/cli.js`, so `__dirname = dist/`, and `pkgRoot = dist/.. = package root`. `cleargate init` reads **ROOT `templates/cleargate-planning`** — NOT `dist/templates/`. A repo-wide grep for a literal `dist/templates` RUNTIME read returns NOTHING (only tsup's onSuccess writer + comments).

  **Conclusion (inverts the CR):**
  - ROOT `templates/` is the LIVE read path. It MUST STAY in `files[]`.
  - `dist/templates/` (written by tsup `onSuccess`, tsup.config.ts:43-49) is the UNUSED duplicate. The redundancy is eliminated by **stopping the `onSuccess` template copy** (so `dist/` no longer carries a second payload), NOT by dropping `templates` from `files[]`.
  - **Developer MUST re-run this proof before touching anything** (grep `resolveDefaultPayloadDir`, confirm `__dirname` math) and record it in the dev report. The CR's "drop `templates` from `files[]`" instruction is WRONG for this codebase — do the inverse.

Alternative — keep emit, exclude via `.npmignore` (`*.map`) — is more fragile (`.npmignore` overrides `files[]` semantics). **Recommend `sourcemap: false`.**
