**(b) Fix design, per layer.**

#### L1 — Dispatcher: symlink resolution (`pre-commit.sh:11`)

Current, verified verbatim at `cleargate-planning/.claude/hooks/pre-commit.sh:11`:

```bash
HOOK_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
```

`${BASH_SOURCE[0]}` is the path bash was *invoked with*. Git invokes `.git/hooks/pre-commit`, a
symlink; bash does not dereference it. `cd`+`pwd` canonicalises the *directory* (`.git/hooks`) but
never the *file*, so `HOOK_DIR=<repo>/.git/hooks`, the `:13` glob `"${HOOK_DIR}"/pre-commit-*.sh`
expands to the literal unmatched pattern, `:14`'s `[[ -f ]]` fails, `continue`, and `:19` `exit 0`.

**Mechanism: `while [ -L ]` + BSD `readlink` loop, with `cd -P` for the final canonicalisation.**

```bash
SOURCE="${BASH_SOURCE[0]}"
while [ -L "${SOURCE}" ]; do
  LINK_DIR="$(cd -P "$(dirname "${SOURCE}")" && pwd)"
  SOURCE="$(readlink "${SOURCE}")"
  case "${SOURCE}" in
    /*) ;;                              # absolute target — take as-is
    *)  SOURCE="${LINK_DIR}/${SOURCE}" ;;  # relative target — resolve against the LINK's dir
  esac
done
HOOK_DIR="$(cd -P "$(dirname "${SOURCE}")" && pwd)"
```

**Why this and not `readlink -f`:** `readlink -f` is GNU coreutils. macOS ships BSD `readlink`
(no `-f`); `bash --version` on this machine is **GNU bash 3.2.57(1)-release (arm64-apple-darwin25)**
— the system bash, which is also what `#!/usr/bin/env bash` picks up when no newer bash is on PATH.
The loop uses only POSIX-portable `readlink <file>` (single-argument form, present on both BSD and
GNU), `[ -L ]`, `case`, and `cd -P`. No `realpath` (also non-POSIX, missing on older macOS), no
`${var//}` extended substitution beyond bash 3.2, no arrays.

**Why `cd -P` and not plain `cd`:** plain `cd` honours `$CWD`-logical symlinked directory paths and
can hand back a path that still contains a symlinked component; `-P` resolves the physical path.
Both spellings must be `-P` — the one inside the loop (used to anchor a relative link target) and
the final one.

**Why the loop and not a single `readlink`:** symlink-to-symlink chains are legal and real (a
`.git/hooks/pre-commit` → `.claude/hooks/pre-commit.sh` where `.claude` itself is a symlinked
directory, or a two-hop install). The loop terminates because each iteration replaces `SOURCE` with
its target; a cyclic link would spin, which is the same failure mode `readlink -f` reports as an
error and is not a case any install recipe produces.

**Both installed forms must work.** The documented recipe
(`cleargate-planning/.claude/hooks/pre-commit.sh:4`, `cleargate-enforcement.md:321`) is the
*relative* `ln -sf ../../.claude/hooks/pre-commit.sh .git/hooks/pre-commit`. **This repo's actual
link is absolute** — verified: `.git/hooks/pre-commit -> /Users/ssuladze/Documents/Dev/ClearGate/.claude/hooks/pre-commit.sh`
(and `.cleargate/sprint-runs/SPRINT-10/STORY-014-01-dev.md:31` records that absolute install). The
`case` split handles both; the E2E test exercises the **relative** form (the documented one) and a
unit-level leg exercises the absolute form.

Nothing else in the file changes. `:13-17` (the glob loop, the `-f`/`-x` guards, `|| exit $?`) and
`:19` (`exit 0`) stay byte-identical.

gitignored (**`.gitignore:22`**, verified: `.cleargate/sprint-runs/.active`) and written only into

**Introduce a SECOND root. Do not move the first one.** This split is the load-bearing design
decision of L2 and CR-086 does not spell it out:

| Root | Resolves to | Consumes |
|---|---|---|
| `REPO_ROOT` (existing, **unchanged**) | current worktree (`git rev-parse --show-toplevel`) | `git diff --cached` (`:160`), whitelist (`:20`), `normalize_path` (`:215`), **story-file lookup (primary)** (`:93`, `:95`) |
| `SPRINT_STATE_ROOT` (**new**) | main working tree | `.active` sentinel (`:21`), `state.json` (`:55`), story-file lookup (**fallback only**) |

Rationale for keeping the story file on `REPO_ROOT`: enforcement `:288` explicitly permits "an
updated §3.1 table committed in the same story (self-amending surface)". If the story file were
read from the main checkout, a self-amendment made in the worktree would not take effect until
merge — the gate would block the very commit that legalises itself. The worktree copy is tracked and
present, so it is both available and correct. Fall back to `SPRINT_STATE_ROOT` only when the
worktree has no matching story file (e.g. the story file was authored on `main` after the worktree
was cut).

**Mechanism:**

```bash
resolve_sprint_state_root() {
  local common parent
  # git >= 2.31: absolute, unambiguous, no CWD-relative normalisation needed
  common="$(git -C "${REPO_ROOT}" rev-parse --path-format=absolute --git-common-dir 2>/dev/null || true)"
  if [[ -z "${common}" ]]; then
    # Fallback for git < 2.31: --git-common-dir may be CWD-relative
    common="$(git -C "${REPO_ROOT}" rev-parse --git-common-dir 2>/dev/null || true)"
    [[ -z "${common}" ]] && { echo "${REPO_ROOT}"; return; }
    case "${common}" in
      /*) ;;
      *)  common="${REPO_ROOT}/${common}" ;;
    esac
  fi
  parent="$(cd "${common}/.." 2>/dev/null && pwd || true)"
  if [[ -n "${parent}" && -d "${parent}/.cleargate/sprint-runs" ]]; then
    echo "${parent}"
  else
    echo "${REPO_ROOT}"
  fi
}
SPRINT_STATE_ROOT="$(resolve_sprint_state_root)"
```

**Derivation in both topologies — measured on this machine, git 2.50.1:**

| Invocation | `rev-parse --git-common-dir` | `--path-format=absolute --git-common-dir` | parent |
|---|---|---|---|
| main checkout, cwd = toplevel | `.git` (relative!) | `/…/ClearGate/.git` | `/…/ClearGate` ✔ |
| main checkout, cwd = `.cleargate/` | `../.git` (relative!) | `/…/ClearGate/.git` | `/…/ClearGate` ✔ |
| linked worktree `.worktrees/CR-086` | `/…/ClearGate/.git` (absolute) | `/…/ClearGate/.git` | `/…/ClearGate` ✔ |

Note the trap the existing precedent falls into: `.cleargate/scripts/test/test_template_gate_correctness.red.sh:104-112`
tests `"${GIT_COMMON_DIR}" != ".git"` — a literal string compare that is correct only when cwd is
exactly the toplevel. From a subdirectory git returns `../.git` and that check mis-classifies a main
checkout as a worktree. Use the `--path-format=absolute` form; keep the `case`-based normalisation
only as the older-git fallback.

**Three fallback behaviours, all required:**
1. `--path-format=absolute` unsupported (git < 2.31) → second `rev-parse` + `case` normalisation.
2. `rev-parse` fails entirely (not a git repo — reachable when `CLEARGATE_REPO_ROOT` points at a
   plain directory) → return `REPO_ROOT`. Preserves today's behaviour exactly.
3. Parent exists but has no `.cleargate/sprint-runs/` directory (separate-git-dir, bare-repo
   satellite, or a `.git` that is not directly under the working tree) → return `REPO_ROOT`. The
   derivation "parent of the common dir is the main working tree" is true for ordinary clones and
   linked worktrees but false for `--separate-git-dir`; the directory-existence probe is what makes
   the heuristic safe rather than merely usual.

**`CLEARGATE_REPO_ROOT` semantics are preserved, not special-cased.** The existing bash harness
`.cleargate/scripts/test/test_file_surface.sh:94,126,160,186` sets `CLEARGATE_REPO_ROOT=<tmpdir>`
and writes `.active` + `state.json` into that same tmpdir (`:71-76`), which `setup_git_repo()`
`git init`s (`:35-41`). `resolve_sprint_state_root` therefore derives `<tmpdir>/.git` → parent
`<tmpdir>` → equals `REPO_ROOT`. **All four of that harness's scenarios must keep passing byte-for-byte
with no edit to the harness.** That is a hard regression assertion, not a nice-to-have.

**Do NOT add a `CLEARGATE_SPRINT_RUNS_ROOT` env override.** An override would give the new node test
a seam that bypasses the exact resolution under test. The E2E test uses a real `git worktree add`.

`STATE_JSON_GLOB` (`:22`) is dead — grep confirms zero other references in the file. Leave it or
repoint it to `SPRINT_STATE_ROOT`; do not delete it (out of sandbox, zero behavioural effect).
Repointing is preferred for coherence.

*first*, then `:134` splits on `", "`, so the delimiter that actually bounds a path (the backtick)
is destroyed before the split. Consequence is a **false BLOCK**, not a silent pass: `declared_paths`
is non-empty (so the `:150` guard does not fire), but no staged file ever equals a sentence, so every
staged file lands in `off_surface` and `:264` exits 1. Also measured: `` **`c/five.ts`** — bolded ``
currently yields `**c/five.ts** — bolded`.

**Mechanism: split the Value cell on `", "` FIRST; from each segment take the FIRST backtick-quoted
span; keep it only if it is whitespace-free and contains `.` or `/`.**

```awk
function first_backticked(s,   a, rest, b) {
  a = index(s, "`");            if (a == 0) return ""
  rest = substr(s, a + 1)
  b = index(rest, "`");         if (b == 0) return ""
  return substr(rest, 1, b - 1)
}
```

Per row: keep the existing section scan (`:118-119`), the pipe-split (`:122-126`), the whitespace
trim (`:128`) and the cheap `if (val !~ /[.\/]/) next` pre-filter (`:130`). **Delete** the
`gsub(/`/, "", val)` at `:132`. Then:

```awk
npaths = split(val, segs, ", ")
for (i = 1; i <= npaths; i++) {
  p = first_backticked(segs[i])
  if (p == "") continue
  gsub(/^[[:space:]]+|[[:space:]]+$/, "", p)
  if (p ~ /[[:space:]]/) continue        # a quoted phrase, not a path
  if (p ~ /[.\/]/) print p
}
```

`index()` + `substr()` only — no `gensub`, no `match()` capture groups, no `RSTART`/`RLENGTH`
bookkeeping. Works on BWK awk (macOS `/usr/bin/awk`), mawk, and gawk alike.

#### (b) W7-L1 — the guard mechanism

**Current, verbatim, `cleargate-planning/.claude/hooks/pre-commit-surface-gate.sh:26`:**

```bash
if ! npm run check:no-vitest -s --prefix mcp 2>/dev/null || ! npm run check:no-vitest -s --prefix cleargate-cli 2>/dev/null || ! npm run check:no-vitest -s --prefix admin 2>/dev/null; then exit 1; fi
```

**Exit shapes re-measured today** (all four, in a scratch dir, `npm run check:no-vitest --prefix X`):

| Shape | Exit |
|---|---|
| no root `package.json`, no `mcp/` | **254** |
| root `package.json` present, no `mcp/` | **254** |
| `mcp/` exists, **no `package.json`** inside | **254** (a shape CR-087 does not enumerate) |
| `mcp/` exists with `package.json`, script **undefined** | **1** |
| `npm` absent from `PATH` | **127** |

`if !` maps every one of these to `exit 1`. **No downstream repo shape passes. Neither does any
linked worktree of this repo** — `mcp/`, `cleargate-cli/` and `admin/` are gitignored here
(`.gitignore:62-64`), so `.worktrees/CR-087/{mcp,cleargate-cli,admin}` do not exist (verified: `ls` →
`No such file or directory` for all three). Once Gate 4 hand-ports the CR-086 dispatcher, **every

sharpest meta-repo-local reason the guard must land before close, and it is test leg **3d**.

**Replacement (exact shape — bash 3.2 portable, no `jq`, no `node`, no arrays, no `readlink -f`):**

```bash
# EPIC-045 carry-over: this prefix list is meta-repo vocabulary living in a file
# that ships to every target repo. Each entry runs ONLY where the directory
# exists AND its package.json actually defines the script, so the chain is inert
# — not fatal — anywhere else. Do not add a SKIP_-style bypass here (CR-087 §4.5).
for _cg_pkg in mcp cleargate-cli admin; do
  _cg_dir="${REPO_ROOT}/${_cg_pkg}"
  [ -d "${_cg_dir}" ] || continue
  [ -f "${_cg_dir}/package.json" ] || continue
  grep -qE '"check:no-vitest"[[:space:]]*:' "${_cg_dir}/package.json" || continue
  if ! command -v npm >/dev/null 2>&1; then
    echo "[surface-gate] WARNING: npm not on PATH — skipping check:no-vitest for ${_cg_pkg}/." >&2
    continue
  fi
  if ! npm run check:no-vitest --prefix "${_cg_dir}"; then
    echo "[surface-gate] BLOCKED: check:no-vitest failed in ${_cg_pkg}/ — vitest residue detected (output above)." >&2
    exit 1
  fi
done
```

**Why each element, with the measurement behind it:**

- **`for … in mcp cleargate-cli admin`** — a literal word list. bash 3.2 has indexed arrays, but a
  literal `for` list needs none and reads as the same hard-coded vocabulary the CR ruled to keep.
- **`_cg_dir="${REPO_ROOT}/${_cg_pkg}"`, absolute, reusing the existing `REPO_ROOT` from `:4`.**
  Reuse, no duplication. It also removes a latent split-brain: today the `[ -d ]` probe (if written
  relative) and the `npm --prefix` call could resolve to different directories if git ever invoked
  the hook from a non-toplevel cwd. Both sides now name the same absolute path. `REPO_ROOT` already
  carries its own `2>/dev/null || pwd` fallback for the non-repo case.
- **`[ -d ]` then `[ -f …/package.json]` then `grep -qE`.** Three checks, cheapest first, each a
  distinct measured failure shape (254 / 254 / 1). Skipping any one of them leaves a live 254 or 1.
- **`grep`, NOT `jq` — deliberate, and here is the justification the dispatch asked for.** `jq` *is*
  already a de-facto scaffold dependency: `cleargate-planning/.claude/hooks/{stamp-and-gate,
  pending-task-sentinel,session-start,pre-tool-use-task,token-ledger,pre-tool-use-autonomy}.sh` and
  `.cleargate/scripts/{pre_gate_common,write_dispatch}.sh` all use it, and only
  `pre-tool-use-autonomy.sh:27` guards with `command -v jq`. **Matching that precedent would still be
  wrong here**, on a blast-radius argument: every one of those is a *Claude Code lifecycle* hook —
  an absent `jq` degrades agent behaviour. This is a *git pre-commit* hook running under
  `set -euo pipefail`, where an absent `jq` is `command not found` → non-zero → **blocked commit with
  no recourse but `--no-verify`**. Introducing a new hard tool dependency into the very hook whose
  defect is "an environment assumption that hard-blocks commits" would re-create the bug class
  CR-087 exists to delete. `pre-commit-surface-gate.sh` has **zero** external tool dependencies today
  (grep of the file: no `jq`, no `node`; its only `node` hits are the literal string `.red.node.test.ts`
  at `:10/:11/:15`). Keep it at zero + POSIX `grep`.
- **The regex `'"check:no-vitest"[[:space:]]*:'`, not a bare substring.** Measured today:
  `{"scripts":{"pre":"npm run check:no-vitest"}}` — a package that *references* the script in another
  script's value without defining it — **false-positives under `grep -q 'check:no-vitest'`** and is
  **correctly rejected** by the colon-anchored form. Under the naive grep that package would be
  handed to npm, which returns 1 ("Missing script"), and we would be back to blocking. Also verified:
  `JSON.stringify({scripts:{'check:no-vitest':'exit 0'}})` (the exact shape CR-086's fixture writes)
  **matches** — `[[:space:]]*` allows the zero-space form. Test leg **4c** locks this regex.
  POSIX bracket class, not `\s`: BSD `grep -E` on macOS does not honour `\s`.
- **`command -v npm` INSIDE the loop, after the three guards.** Placing it outside would emit a
  spurious warning on every commit in every non-node repo. Inside, a downstream repo never reaches
  it (zero output, zero cost); a repo that *has* the packages but no npm gets one named warning per
  package and **exit 0** — non-applicability, not a block. This replaces the measured **127**.
- **`set -euo pipefail` safety.** Every fallible command sits in an `if !` or a `|| continue`, both
  of which disarm `-e`. **Do NOT capture grep into a variable** (`X=$(grep …)` under `-e` aborts on
  no-match; and see FLASHCARD 2026-06-03 `#test-harness #bash` for the adjacent `grep -c … || echo 0`
  doubling trap). `_cg_pkg`/`_cg_dir` are the file's only loop variables — no collision with `:4-24`.
- **Position: exactly where `:26` sits today** — after the CR-043 red-gate block (`:6-24`), before
  the `SCRIPT=` resolution (`:28`). Ordering is load-bearing for leg 3: the package check must still
  fire *before* the surface-gate delegation, so a genuine vitest residue blocks even when the surface
  gate would exit 0 at E5.

#### (c) Diagnosability — where `-s` and `2>/dev/null` go, and what a failure looks like

**Both are dropped.** CR-087 §0.5 Q3 (human-RESOLVED) rules `-s`; the plan additionally drops
`2>/dev/null`, because **measured byte counts show `2>/dev/null` — not `-s` — is what erases a
genuine failure**:

| Invocation | stdout | stderr |
|---|---|---|
| missing dir, `-s` | **0 B** | **0 B** |
| missing dir, no `-s` | 0 B | **559 B** (npm's ENOENT / could-not-read-package.json) |
| script present and **failing**, `-s` | 0 B | **23 B** (the script's own `console.error` survives `-s`) |
| script present and failing, no `-s` | 88 B (npm banner) | 23 B |

So `-s` alone silences only the *npm-level* (missing-prefix) failure; the *script-level* failure is
silenced by the `2>/dev/null` that line 26 also carries. Dropping only `-s` would leave assertion 2
red. **Drop both.**

**Failure output after the fix**, for a real residue in `cleargate-cli/` (shape measured today):

```
> @cleargate/cleargate@X.Y.Z check:no-vitest
> node -e "…"

vitest residue detected:
./src/foo.ts:12:  vi.fn()
[surface-gate] BLOCKED: check:no-vitest failed in cleargate-cli/ — vitest residue detected (output above).
```

**The hook's own `[surface-gate] BLOCKED:` line is mandatory, not decorative.** Two measured reasons:
(i) npm's banner names the package only when `package.json` has both `name` and `version` — a stub
with `name` but no `version` printed a bare `> check:no-vitest`, naming nothing; (ii)
`npm_config_loglevel=silent` **propagates into nested `npm run` children** (verified: an inner
`npm run` under an outer `npm run --silent` sees `npm_config_loglevel=silent`), so anyone invoking
`git commit` from inside an `npm … --silent` context re-silences the banner. The hook's own stderr
line is unconditional and immune to both. Assertion 2 must match on that line, not on npm's banner.

**Happy path in a downstream repo stays perfectly quiet — zero bytes, zero cost.** The three `[ -d ]`
probes fail, `continue` fires three times, npm is never invoked. Silence is free precisely because
the guard means the command does not run. (Verified structurally: the `echo` inside the loop is
unreachable without a present directory.)

**Happy path in the meta-repo becomes noisy, by design.** All three packages exist, all three define
the script, all three **pass today** (re-verified: `mcp` exit 0, `cleargate-cli` exit 0, `admin`
exit 0). Cost measured: **~5.8 s wall** for the three sequentially (`mcp` alone is ~4.8 s — its
`grep -rE` walks `node_modules`), and ~15 lines of banner+output. That cost is pre-existing to line
26, not introduced here; it becomes *visible* for the first time at Gate 4 when the live dispatcher
is hand-ported. Flag it in the Gate-4 handoff.
