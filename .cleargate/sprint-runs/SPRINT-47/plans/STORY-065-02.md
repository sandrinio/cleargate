## Decisions (the Developer executes these)
1. **Command source chain.** A new additive export in `lib/proof.mjs`: `resolveProofCommand(content: string|null, tier: string|null, gateChecks: object|null): string|null`. It tries, in order, and returns the first non-blank value, trimmed:
   1. `parseProofCommand(content)`
   2. `gateChecks.proof[tier]`
   3. `gateChecks.qa.test`, only when `tier === 'unit'`

   Both `record_evidence.mjs` (when no `--` command is given) and `prep_qa_context.mjs` `buildCommands` call it. That is how Outline row 3 has QA-Verify name `make t` as well.
2. **Root and sprint dir.**
   - `ROOT = sprintRoot(resolve(SCRIPT_DIR,'..','..'))`, using `lib/sprint-root.mjs`, as `seal_red.mjs:24` does.
   - Sprint dir: `CLEARGATE_SPRINT_DIR`, else `ROOT/.cleargate/sprint-runs/<.active trimmed>`. If neither exists, or `.active` is empty, exit 2.
   - Item: `findItemFile(ROOT, id)`.
   - Config: `SCRIPT_DIR/gate-checks.json`, the file `prep_qa_context.mjs:574` reads. If it is unreadable, treat it as `{}`.
3. **Order of checks, so that any exit 2 happens before anything runs.** Parse the arguments, then the sprint dir, then the mode and tier, then `--worktree` (it must be an existing directory), then the command. Then run.
4. **Tier.**
   - `--tier`, else `readProofTier(item)`. If there is none, the reason is `no proof tier for <ID>`. If the value fails `isProofTier`, the reason is `invalid proof tier '<t>' for <ID>`.
   - **`--human "<note>"`** always records `tier: 'human'`, `mode: 'human'`, `status: 'pass'`. If the resolved tier is non-null and is not `human`, exit 2 with `--human records a human-tier proof; <ID> declares <t>`. An empty note exits 2 with `--human needs a note`. Combining `--human` with `--` exits 2 with the usage line.
5. **Modes.**
   - A command after `--` is the arguments joined with spaces.
   - When no command resolves: `unit` or `container` exit 2. `live` or `human` write `pending` and exit 0, with `command`, `note` and `exit_code` all null, `tail` `[]`, and `duration_ms` 0.
   - When the item has a command, `human` and `live` run it, as R1 states literally (see Risks).
6. **The run.** Use async `spawn('bash', ['-c', cmd], {cwd, env: commandEnv(), detached: true})`.
   - Collect stdout and stderr in arrival order, keeping at most 64 MiB and dropping from the front.
   - Timeout is `CLEARGATE_PROOF_TIMEOUT_S`. A value that is missing, non-numeric or ≤0 means 1800. On timeout: `process.kill(-pid,'SIGTERM')`, then SIGKILL after 2 s, and resolve after 5 s even if `close` has not fired.
   - A timeout records `status 'fail'`, `timed_out true`, `exit_code 124`, plus a last tail line `record_evidence: timed out after <N>s`. The tail stays at 40 lines or fewer.
   - If bash cannot start (spawn `error`), exit 2 with `could not start bash: <msg>`. A non-zero exit, 127 included, records `fail` and exits 1.
   - `sha` comes from `git -C <runDir> rev-parse HEAD`, or null. `duration_ms` is wall time.
7. **Masking.** Mask each env var whose upper-cased name contains `TOKEN`, `SECRET`, `KEY` or `PASSWORD` and whose value is at least 4 characters. Replace every occurrence with `***`, longest values first. This applies to `tail` only. Run `extractFailing` on the raw output before masking.
8. **Baseline excuse.** Read `<sprintDir>/baseline.json`. Excuse the run only when all of these hold:
   - the mode is command, `exit_code !== 0` and the run did not time out;
   - `cmd.trim() === baseline.command.trim()`;
   - `extractFailing(raw)` is non-empty and is a subset of `baseline.failing`.

   An excused run records `status 'pass'`, `excused 'baseline'`, `excused_failing` = those names, and the real `exit_code`. The CLI exits 0. Do not import `merge_story.mjs` `judgeTestFailure`: it has an extra unnamed-failure path, and the file is 03's.
9. **Write and entry guard.**
   - `mkdir -p evidence/`, write `<file>.tmp.<pid>`, then rename. Re-running overwrites the file, so the latest result wins.
   - The entry guard compares realpaths, as `record_baseline.mjs:275-281` does, and the async `main` resolves to the exit code. The C1 stub's guard (`record_evidence.mjs:34`) compares unresolved paths, so a symlinked path silently runs nothing. Replace it.
   - An unexpected error before the write exits 2 with `record_evidence: <msg>`.
10. **Gate config (R4 and R5): one mechanism.** Add `proof.unit` and `proof.container` to the existing `GATE_FIELDS` plan, as R4 states. Do not build a parallel `planProof`.
    - `planGateCommands` reads `prior?.[field] ?? ''`. Without this, three-key priors produce `to: undefined`.
    - Detected values: `proof.unit` is the same value as `qa.test`; `proof.container` is `stack.containerProofCmd ?? ''`, independent of `resolved`.
    - `detectTestStack` sets `containerProofCmd: 'make e2e'` when the root `Makefile` has a line matching `/^(?:[\w./%-]+\s+)*e2e(?:\s+[\w./%-]+)*\s*::?(?!=)/m`, and `''` otherwise. Set it on every return path, by wrapping the existing body.
    - `renderGateChecks` writes a proof field only when the file already has a `proof` object or the value is non-empty.
11. **Upgrade keeps user keys (R5).** In `detect-test-stack.ts`:
    - `mergeUserGateKeys(base, prior)` deep-adds every key path in `prior` that `base` lacks. It recurses into plain objects only; arrays and scalars are leaves, and keys are appended in `prior` order. It then sets every non-empty string `prior.proof.*`.
    - `projectGateChecks(pkgRaw, plan, priorRaw?)`: apply the plan, then the merge. If nothing changed, return `pkgRaw` verbatim.
    - Export `readGateChecksRaw(dir): string|null`.
    - Export `keepUserGateKeys(dir, priorRaw): boolean`. It merges into the current file, writes only on change and never throws.
    - `gateChecksHasLocalEdits` also strips the whole `proof` object from both sides, and prunes from the disk side every key path that the package lacks.

    In `upgrade.ts`:
    - Read `priorGateRaw` next to `priorGate` (:786).
    - Pass it through `fileOutcome` (:322) and `applyAlwaysOverwrite` (:390); the call sites are :404, :952 and :1109.
    - In `applyAlwaysOverwrite`, when the file is `GATE_CHECKS_REL` and the outcome is `unchanged`, update the snapshot entry and return before `writeAtomic` (:407). This is the "neither rewrites" requirement.
    - After `applyTestStack` (:1255), call `keepUserGateKeys`, then `restoreTestWaiver`.
    - Print the waiver `kept` line whenever `priorWaiver.trim()` is non-empty and `readTestWaiver(cwd) === priorWaiver`, not only when it wrote (U1 below).
