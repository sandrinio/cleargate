## How M1 advances the Sprint Goal

Sprint Goal clause 1: *"a pre-sprint SPIKE charter for bounded discovery."* M1 is that clause, delivered end to end. One sentence per story:

- **STORY-054-01** ships the document shape a spike can actually be written in — the one template in the corpus whose contract is *"the answer is unknown at draft time"* — without which "author a spike" has no artifact.

M1 does not touch the Task Breakdown surface (M2) or the gate-index defect (M0, shipped). It **consumes** M0: STORY-054-02 appends to the registry M0 corrected and extends the enumerating test M0 built.

### Schema — the exact heading layout (NORMATIVE; binds 054-02)

`section(N)` is **the Nth `## ` heading in document order** — verified: `evalSection` (`readiness-predicates.ts:640-648`) splits on `/^(?=## )/m`, and with a preamble (`# {ID}: {SLUG}` H1) `arrayIndex = N`, so `rawParts[N]` is the Nth heading. The template body **must** carry exactly these six `## ` headings, in this order, with these exact strings:

| Position | Heading line (exact, including punctuation) |
|---|---|
| 1 | `## 1. The Question` |
| 2 | `## 2. Timebox & Kill Criteria` |
| 3 | `## 3. Decision Unblocked` |
| 4 | `## 4. Decision Log` |
| 5 | `## 5. Outcome & Spawned Items` |
| 6 | `## ClearGate Ambiguity Gate (🟢 / 🟡 / 🔴)` |

**No other `## ` heading.** Specifically: **no `## 0.5 Open Questions`** (a spike *is* the open question; adding it shifts every index and is self-parody), **no `## Existing Surfaces`**, **no `## Why not simpler?`**, **no `## Context Source`**. §1.2 Requirement 1 is an exhaustive ordered list; Requirement 4 adds the Ambiguity Gate. Every additional heading costs a position that 054-02 must then recompute. `## Prior work` is an **open decision** — see §Open decisions #1; the default is **omit**.

**T5 applies (M0 post-flight):** `resolveHeadingLine` returns the **full heading line**, parentheticals included. Heading 6 carries a parenthetical and embedded emoji — but it is not a gated position, so no fixture row. Headings 1, 2, 4, 5 **are** gated by 054-02 and must carry **no parenthetical**, because the fixture rows in §STORY-054-02 below pin them verbatim.

**Deviation from this table is a QA kick-back on 054-01, not a re-index by 054-02.** If a heading must change, it changes here, before 054-02 is dispatched.

### Template invariants (NORMATIVE — each is a QA kick-back criterion)

These make 054-02's gate criteria non-vacuous and keep the template out of three known traps.

1. **Zero `- ` bullet lines inside §1, §2, §4, §5 — including inside code fences.** `evalSection`'s `listed-item` branch matches `/^\s*- /gm` against the raw section text and **does not strip fences** (verified `readiness-predicates.ts:668`). Guidance in those four sections is prose, bold sub-labels, or a table — never a bullet. This is the reason 054-02's presence criteria have teeth: the shipped template scores **0**, so a criterion passing means an author actually wrote something. (Contrast BUG-050: a shipped `**Modify:**` label scores 1 for `declared-item` and makes the criterion vacuous. That trap is avoided here by construction, not by predicate change.)
2. **§4 Decision Log ships as a markdown table: header row + `|---|` separator + ZERO data rows.** `countDeclaredItems` counts table data rows only *after* a separator, and a `|`-leading line cannot match the definition-list-term regex (`/^(\*{1,2}|_{1,2})?[A-Z][^|*\n]*(\*{1,2}|_{1,2})?:/` excludes `|`). So the shipped §4 scores `declared-item` = **0**. This is also the cleanest expression of Requirement 3's "append-only, one entry per discovery round".
3. **The literal string `TBD` appears nowhere in the file.** 054-02 adds `no-tbds` (`body does not contain marker 'TBD'`) to both spike gate blocks. A template shipping `TBD` fails its own gate on first render.
4. **No literal `SPRINT-<digits>` token anywhere in the post-frontmatter body.** Write `SPRINT-NN` or `SPRINT-<n>`. Recorded as a `sprint-context.md` Mid-Sprint Amendment guard note (M0 R12). Free now, expensive after the template ships. Occurrences inside `<instructions>` are harmless under both render paths (M0 R12 correction) — **do not spend effort purging those**; just do not create body-level ones.
5. **No line consisting of exactly `---` inside the `<instructions>` block.** `templateBodyOf` (`gate-section-index-pinning.node.test.ts:219-224`) locates the frontmatter with `/^---[ \t]*\r?\n[\s\S]*?\r?\n---[ \t]*\r?\n/m` — the **first** `---`-delimited pair in the raw file. A horizontal rule inside `<instructions>` would be mistaken for the frontmatter opener and every downstream index would be computed against garbage. A `---` **after** the frontmatter is fine (`hotfix.md:100` has one).
6. **No `## `-leading line inside a code fence anywhere in the file.** FLASHCARD 2026-07-19 `#test-harness #readiness-gates`: `body.split(/^(?=## )/m)` ignores fences, so a fenced `## Example` creates a phantom section and shifts everything below it. Verified: none of the nine shipped templates does this today. `spike.md` must not be the first.
7. **`<instructions>` closes with `Do NOT output these instructions.`** — house pattern, `hotfix.md:27`.
