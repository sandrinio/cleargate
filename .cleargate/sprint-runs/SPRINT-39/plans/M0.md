## How M0 advances the Sprint Goal

The Sprint Goal has three clauses; M0 owns the third and is the hard gate on the second.

- **"repair the gate-index defect"** — BUG-042 *is* that clause. Three `section(N)` criteria in `readiness-gates.md` name a heading and evaluate a different one. Two of them (`cr.sandbox-paths-declared`, `epic.affected-files-declared`) leave the CR Execution Sandbox and the Epic Affected Files list **gated by nothing**, and the failure presents as a green 8/8 or 12/12 pass, so it reads as "checked and fine" rather than "not checked". Correcting the three indices moves the sprint's declared metric from **9/12 → 12/12**.
- **"that blocks the second one"** — the Task Breakdown surface (STORY-054-06, M2) inserts a `## Task Breakdown` heading into `story.md`, `CR.md` and `Bug.md`. Every insertion shifts positional indices. Landing 054-06 on an uncorrected, unpinned registry means converting a wrong index into a *differently* wrong index with nothing to notice. M0 is what makes M2 a build-break instead of a silent redirect.
- **"a pre-sprint SPIKE charter"** — STORY-054-02 (M1) appends two spike gate blocks to the same file and must rebase on M0's corrections; STORY-054-01 ships `spike.md`, a new template whose own section indices will be authored against the corrected mental model. M0 lands the correct model first.

STORY-054-05 is not a nice-to-have half. **The metric is "criteria resolving to their named heading", not "criteria carrying the right number today."** A test that pins literal integers records the current numbers and asserts nothing about naming; it would go green on a tree where `## Task Breakdown` shifted `sandbox-paths-declared` off Execution Sandbox again, because the integer would still be 6. Only a test that resolves index → heading text and compares that text to an independently-authored statement of intent moves the metric — and keeps it moved. See **§Test shape**, which is normative, not advisory.

### Required fourth edit — the vocabulary note

The Predicate Vocabulary entry at `readiness-gates.md:27-34` says *"Splits the document body on `## ` heading boundaries (1-indexed)"* and never states that the **printed ordinal is not the index**. That silence is the authoring defect: three criteria were written by people who believed they were counting correctly. Correcting the numbers without correcting the doc ships the same trap to the next author — and EPIC-052 and STORY-054-06 are both queued to add headings.

Append to the `section(<N>)` entry (after the two `Example:` sentences at `:34`), both trees, verbatim:

```markdown
**`N` is a position, not a printed ordinal.** Sections are counted in document order over `## ` headings, so a template whose first heading is `## 0.5 Open Questions` or `## 0. AI Coding Agent Handoff` shifts every later section by one — and unnumbered headings (`## Existing Surfaces`, `## Prior work`, `## Why not simpler?`) consume positions too. `## 3. Execution Sandbox` in `CR.md` is `section(6)`, not `section(3)`. Inserting any `## ` heading into a gated template renumbers every criterion below it. The pinning test (`cleargate-cli/test/docs/gate-section-index-pinning.node.test.ts`) enumerates every `section(N)` criterion and asserts it resolves to the heading its id names — it is what turns that renumbering into a build break. Update the fixture there in the same commit as any template heading change.
```

This paragraph is inside a prose section of a file that is never itself gate-evaluated, so it shifts nothing.

### Red-phase contract (normative — resolves the "test-only story has no Red" problem)

BUG-042 merges first, so a test that only pins live indices is **green on authoring** and never demonstrates it can fail. That is precisely the failure mode the dispatch brief warns about. The Red phase is therefore relocated, not skipped:

- **Red comes from the mutation scenarios (S2, S3, S5 below).** They drive the checker against *synthetic mutated copies* in a tmpdir and assert it reports a specific named failure. They are red until the checker exists and stay red-capable forever — they do not decay the way "three transient failures against a pre-fix tree" would.
- **Ratio:** of the 6 scenarios, 3 are positive (live tree) and 3 are mutation. **A submission whose only assertions read the live tree is a QA kick-back**, regardless of green.
- Red-test file naming for the QA-Red artifact: `*.red.node.test.ts` (matches `test/**/*.node.test.ts` in `run-default-tests.mjs:24`, so it is picked up by the default runner). Precedent and header shape: `cleargate-cli/test/lib/readiness-predicates-heading-anchor.red.node.test.ts:1-21`, which documents its own `Expected baseline fail count: 3`. **Failure-message contract (Requirement 3), one line per finding:**

```

```

Assert on the message text in S2/S3, not merely on `assert.throws`. A pinning test whose failure output does not name the criterion sends the next reader back to re-derive the split by hand — which is how this defect was born.
