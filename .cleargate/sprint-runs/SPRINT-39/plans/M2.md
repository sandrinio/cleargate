### N1 — `task-breakdown-complete` is a NAMED predicate. Ruling: agreed, with code-level proof.

The pin was argued from `section(N)`'s inability to express "passes on absence". That argument is
correct and there is a second, harder one: `evalSection` is the *only* branch that can express a
count, and **Cross-Cutting Rule 3 freezes it for the whole sprint**
(`readiness-predicates.ts:632-657`, read-only, not exported). A `section(N)` form of R5 would
require either editing frozen code or accepting a hard `section N not found` on every legacy item.

Measured, on the real evaluator:

- `evalSection` returns `pass: false, detail: "section N not found (body has M sections)"` when the
  index overruns (`readiness-predicates.ts:648-655`). There is no absence-tolerant mode.
- The three existing named predicates — `existing-surfaces-verified` (`:894`),
  `prior-work-recorded` (`:995`), `ambiguity-gate-resolved` (`:1052`) — all locate their section by
  `body.split(/^(?=## )/m)` + `headingTitleOf` and all three return `pass: true` on absence. That is
  the shape R5 describes, verbatim, three times over.
- As a named predicate, `enumerateSectionCriteria`
  (`gate-section-index-pinning.node.test.ts:183-206`) never keys on it — it calls `parsePredicate`
  inside a `try` and `continue`s on anything that is not `kind === 'section'` (`:191-195`).
  **Measured: S1a's `18`/`16` (`:433`/`:435`) and S6's `16` (`:645`) did not move, and
  `expected-headings.ts` needed zero edits — the pinning test ran 14 pass / 0 fail / 0 skipped
  under the complete change.**

**Adding the predicate is a four-site edit in one file, plus one doc site.** All in the same commit:

1. `readiness-predicates.ts:12-23` — add `| { kind: 'task-breakdown-complete' }` to the
   `ParsedPredicate` union.
2. `readiness-predicates.ts:~130` — add the closed-set branch in `parsePredicate`, immediately after
   the `ambiguity-gate-resolved` branch (`:129-132`).
3. `readiness-predicates.ts:~181` — add `case 'task-breakdown-complete': return evalTaskBreakdownComplete(doc);`
   to the `evaluate` switch (after `:181`).
4. End of file — the `evalTaskBreakdownComplete` function (verbatim in §Schema below).
5. `readiness-gates.md` Predicate Vocabulary (`:8` and the entry list) — "exactly **9** predicate
   shapes" → **10**, plus entry **10**. Both trees.

`evalSection` is **not touched**. `git diff` on `readiness-predicates.ts:632-657` must be empty —
this is a QA kick-back criterion, and S4 (`:594-608`) pins the three lines the checker replicates.

### N2 — Present-case semantics: teeth, not vacuity. (This plan decides it; the story does not.)

R5 fixes the absent case. The story never says what the criterion asserts when the section *is*

```ts
// ─── Task-breakdown-complete evaluator ────────────────────────────────────────

/**
 * STORY-054-06: Verify that a `## Task Breakdown` section, when present, carries at
 * least one task row. Migration grace: section entirely absent → pass (every item
 * authored before this criterion existed lacks it, and R3 says an L1 item omits it
 * deliberately). Present but row-free → fail — this is the teeth: the scaffolded
 * template body deliberately ships zero rows, so an unfilled freshly-authored item
 * fails until the author writes the sequence or deletes the section.
 *
 * Counts `- [ ]` / `- [x]` rows only — NOT `listed-item` and NOT `declared-item`.
 * countDeclaredItems (L712) scores bare bold labels and ordinary prose (BUG-050),
 * and `listed-item` would be satisfied by the guidance block if it ever grew a
 * bullet (BUG-054). A checkbox row is the one shape the guidance cannot accidentally
 * emit.
 *
 * Section locator clones evalPriorWorkRecorded's heading-anchored pattern
 * (`body.split(/^(?=## )/m)` + `headingTitleOf` exact match). headingTitleOf strips
 * numeric prefixes, so `## 3.5 Task Breakdown` in an authored instance still matches.
 */
function evalTaskBreakdownComplete(doc: ParsedDoc): { pass: boolean; detail: string } {
  const rawParts = doc.body.split(/^(?=## )/m);
  let sectionContent: string | undefined;
  for (const part of rawParts) {
    const firstLine = part.split('\n')[0] ?? '';
    if (headingTitleOf(firstLine) === 'Task Breakdown') {
      sectionContent = part;
      break;
    }
  }

  if (!sectionContent) {
    return {
      pass: true,
      detail: `not-applicable: ## Task Breakdown section absent`,
    };
  }

  const rows = (sectionContent.match(/^\s*- \[[ xX]\]/gm) || []).length;
  if (rows === 0) {
    return {
      pass: false,
      detail: '## Task Breakdown is present but carries no `- [ ]` task rows',
    };
  }

  return {
    pass: true,
    detail: `## Task Breakdown has ${rows} task row${rows === 1 ? '' : 's'}`,
  };
}
```
