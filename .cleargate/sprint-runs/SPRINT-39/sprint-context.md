## Cross-Cutting Rules

Sprint-wide architecture rules and UI/API tokens that every story must honour. Populated from the parent Epic's `<architecture_rules>` block.

1. **Two-tree edits are atomic.** Any change under `.cleargate/knowledge/**` or `.cleargate/templates/**`
   MUST land byte-identically in `cleargate-planning/.cleargate/**` in the SAME commit. A story that
   edits one tree is **incomplete regardless of green tests**. Verify with
   `diff <live-path> cleargate-planning/<same-path>` before committing.
2. **`cleargate-cli/templates/cleargate-planning/**` is GENERATED — never hand-edit, never commit.**
   It is gitignored in the `cleargate-cli` repo and regenerated by `npm --prefix cleargate-cli run prebuild`.
   Payload regeneration is a **Gate-4 / close** step, not a per-story one.
3. **`evalSection` is frozen for the whole sprint.** `cleargate-cli/src/lib/readiness-predicates.ts:632-657`
   is read-only and must not be exported. `git diff` on that file is empty for BUG-042 and STORY-054-05.
   Import the already-exported `parsePredicate` (`:43`) and `headingTitleOf` (`:459`) instead of
   re-implementing a predicate parser — a divergent parser guarding a parser defect is the BUG-041 shape.
4. **Inserting a `## ` heading into a gated template renumbers every `section(N)` criterion below it.**
   `section(N)` is a **position**, not a printed ordinal. Any story that adds a template heading
   (STORY-054-06, CR-111, STORY-054-01, STORY-054-02) MUST, in the same commit: recompute which criteria
   shift, correct those `section(N)` values in `readiness-gates.md` (both trees), AND update the fixture
   at `cleargate-cli/test/fixtures/gate-section-index/expected-headings.ts`. **Editing the fixture to
   match whatever the tree now produces is a QA kick-back** — it silently re-breaks the gate.
5. **Never `--no-verify`.** Never `git reset --hard`, force-push, or rewrite history. If a hook fails, fix the cause.
6. **Commits made *inside* `cleargate-cli/` are UNGATED — verify by hand.** Verified 2026-08-27:
   `cleargate-cli/.git/hooks/` contains only `*.sample` files and no `core.hooksPath` is configured, so
   **zero** hooks are installed in that repo. Every commit made from the `cleargate-cli` checkout therefore
   bypasses the surface gate, `check:no-vitest`, `check:no-inline-id-regex`, **and** the typecheck/test
   pre-commit — silently, without anyone passing `--no-verify`. STORY-054-05's three commits were ungated
   this way. The outer repo *does* have a `pre-commit` hook, and `.cleargate/config.yml` `gates.precommit`
   runs cli typecheck + tests, so **outer**-repo commits are gated; cli-repo commits are not.
   Until this is fixed (filed as [[BUG-053]]), any story committing inside `cleargate-cli` MUST run
   `npm --prefix cleargate-cli run typecheck` and the test suite explicitly, and report both numbers in its
   report. Rule 5 still stands, but understand that for cli commits it is currently vacuous — there is no
   hook to bypass. Do **not** install hooks there mid-sprint: the outer hook resolves `.cleargate/**`
   relative to its own root and would misbehave from inside `cleargate-cli`.
