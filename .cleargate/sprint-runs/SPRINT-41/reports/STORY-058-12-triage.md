## Runtime is currently incomplete

1. `commands/workflow.ts:12` hashes the whole plan file and compares it to a `planHash` contained inside that same file. This is a self-referential digest, not a usable plan contract. Compute hashes of canonical payloads excluding their identity/hash fields, or place the digests in the immutable external run manifest. Define one function and use it for create/resume. Config hash comes from config content independently. Reject malformed input before any lock/spawn.
2. The same function installs `gates:{}`, `git:{}` and a hardcoded BLOCKED dispatcher. A user cannot supply an actual configured dispatcher. `resume` merely changes the blocker text; CLI registration requires plan/config again (`src/cli.ts:739-743`) instead of restoring a persisted run. Replace this wiring with real adapters; do not remove the blocker by returning unconditional GREEN.
3. `roles.ts` contains only model constants and an instruction hash. It does not load complete role instructions, create threads/turns, await terminal turn events, parse role results, or persist actual identity. Implement those operations using the pinned external transport, with explicit cwd, model and full developer instructions. No conversation-private APIs.
4. `gates.ts` only wraps a numeric callback; it is unused by the CLI. `engine.ts:11,45` allows an absent gate. Production must require configured real gate commands through the existing wrapper; missing checks block. Conditional TPV/post-flight follows actual scan outcomes, not exclusively arbitrary plan booleans. Deterministic tests can inject decisions, but the production adapter cannot default them to pass.
5. `worktrees.ts` verifies a Git root and exposes a generic argv Git wrapper only. There is no story worktree lifecycle, approved base/head validation, shared branch lease, receipt recovery, DevOps role merge or state-command bridge. Add those planned functions. The engine's serial `git.merge` seam must be implemented by a guarded DevOps role dispatch, not by the orchestrator directly merging. Verify actual ancestry after the role returns; report remains outside teardown targets.
6. `journal.ts:13` accepts malformed JSON at the last *newline-terminated* record (`i === lines.length-2`) but rejects the actual un-terminated tail (`length-1`). Distinguish record completion by delimiter, reject corruption in every complete record, and safely truncate/quarantine only the incomplete tail before future append. Otherwise next append concatenates onto a broken record. Validate increasing sequence and duplicated/divergent identities. `close():11` must remove only its own acquired lock, never another writer's lock. Add proved-dead-process recovery; a crashed coordinator currently strands `.lock` permanently.
7. `engine.ts:14` does not await an async journal append, so an intent need not be durable before the effect. Make ordering awaited; reject missing persistence ports in production. Journal currently records few phase details and no persisted thread/turn identities or immutable executor/config manifest. Add the required identity fields rather than relying on an instruction hash alone.
8. Transport discards ordinary notifications (`codex-transport.ts:14`), so it cannot await real turn completion or distinguish acknowledgement from active turn. It accepts only numeric approval IDs while the pinned fixture has a string request ID; denial is therefore not sent. Generalize valid RPC IDs, surface approval BLOCKED state, and reconcile interrupt races after observing turn activation. Drain stderr to prevent child pipe stalls, reject pending work on stdin/process failure, and await child termination on close. A constant `approvalsGranted=0` is not proof of actual denial.
9. `types.ts` substitutes RED for the required ESCALATED vocabulary and exposes no full plan ownership/surface/context schema. Restore GREEN/ESCALATED/BLOCKED and structured blockers/counters. Validate positive bounded parallelism, story/wave uniqueness, paths, base SHA and resolved role inputs. A zero worker count or absent port must not yield GREEN with no work.

These are planned surfaces, not new feature scope. Existing files can carry the fixes. Additional focused `test/workflow/journal.node.test.ts`, `roles.node.test.ts`, and `workflow.integration.node.test.ts` should exercise real persistence/Git and public CLI wiring; keep sealed reds unchanged.
