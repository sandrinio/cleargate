Add one module, `CLI_ROOT/src/lib/frontmatter-locator.ts`, with this minimal framing API:

```ts
export interface FrontmatterSpan {
  readonly start: number;      // opening delimiter starts
  readonly end: number;        // after closing "---", before its line ending
  readonly yamlStart: number;
  readonly yamlEnd: number;
  readonly eol: '\n' | '\r\n';
}

export function locateFrontmatter(raw: string): FrontmatterSpan | null;

export function replaceFrontmatter(
  raw: string,
  span: FrontmatterSpan,
  serializedBlock: string,
): string;
```

Offsets are JavaScript string offsets, not byte offsets. Callers derive spans from the same unchanged `raw` they replace.

Decisions for implementation:

- Scan lines without normalizing the source. Accept standalone, column-zero `---` delimiters with LF or CRLF, including a closing delimiter at EOF. Preserve an initial BOM as preamble.
- Permit arbitrary leading prose and the complete `<instructions>` block. Treat instruction contents and Markdown fenced examples in the preamble as opaque so embedded example delimiters cannot become the document header. This needs a small line scanner, not a Markdown dependency.
- Select the first eligible opener and its first exact closer. Do not search for a later valid YAML block after malformed YAML. An unterminated opener or unterminated protected preamble is an error.
- Return `null` only for genuinely absent frontmatter. The stamp writers retain their existing creation behavior for that case. They must not catch malformed existing frontmatter and substitute the create branch.
- After a valid block, all remaining text is body, including horizontal rules or further fenced examples. Do not merge multiple blocks or repair already-corrupted documents.
- `replaceFrontmatter` returns `raw.slice(0, start) + renderedBlock + raw.slice(end)`. Render the existing serializer’s LF separators using the located block’s EOL convention. Preserve every byte outside the replaced span, including closing-fence newline, blank lines, Unicode, trailing spaces and EOF shape.
- For parser consumers, `body` remains content after the closing-fence line with one immediately following empty line removed—the existing convention. It excludes the preamble. Writers use raw slices instead of this convenience representation.

The preservation guarantee is exact bytes outside frontmatter and semantic preservation of untouched YAML fields, not preservation of YAML comments or quoting.
