**What "hooks fire in a real Codex CLI session" means (Goal check 4, concretely).**
- **The session.** It is a clean room from the packed artifact (M4 procedure), with `cleargate init --yes --host codex` and `PINNED_CODEX` driven through `codex app-server` stdio. `CODEX_HOME` and `HOME` are dedicated, the environment is scrubbed, and workspace trust plus exact-hash hook trust are recorded.
- **Discovery.** `hooks/list` lists every `.codex/hooks.json` registration: untrusted before trust, trusted after.
- **SessionStart.** SessionStart `completed`, with a `context` entry matching `^ClearGate state: `.
- **Edit, allowed.** An apply_patch on the probe epic produces PreToolUse `completed`, PostToolUse `completed`, `gate-check.log` `stamp=0 gate=0 ingest=0`, and intact frontmatter.
- **Edit, denied.** An apply_patch in enforce mode with no approved story produces PreToolUse `blocked` and leaves the file absent. After the probe story is approved, the same patch proceeds.
- **Dispatch, denied.** A spawn with an unprocessed flashcard produces PreToolUse `blocked` and no child agent.
- **Dispatch, allowed.** After the card is marked processed, the spawn yields exactly one codex sentinel, one SubagentStop, and one `codex-identity … metering=unavailable` log line. The ledger gains no row.
- **Machine checks.** `cleargate verify-install` exits 0.
- **Capture.** The headless evidence is the app-server notification stream: `hook/completed.run.{eventName,status,entries}`, plus `item/*`. This is the Codex counterpart of M4's `claude -p --include-hook-events`.

Two providers drive the same checks:
- **`scripted`** — the real pinned binary with a scripted Responses endpoint. Deterministic, $0, and needs no login. Gating at every run.
- **`live`** — a logged-in `DEDICATED_CODEX_HOME` and a real model. Required at least once, at RS-4 (OD1, OD3).

## Architecture decisions (binding on both blueprints)

**AD-1 — Shared hook scripts: a single canonical source, with generated Codex copies.** The Codex hooks are byte-identical copies of the canonical Claude scripts, generated at `scaffold/hosts/codex/.codex/hooks/<name>.sh` by `scripts/build-codex-payload.mjs --write`. Prebuild runs `--check`, which fails the build on any divergence. `.codex/hooks.json` references the copies.

That violates EPIC-058 `<rule>` "`.codex/**` for Codex-native assets … `.claude/**` for Claude Code". | **(N)** Move the logic to `.cleargate/hooks/` behind Claude wrappers | All 9 installed Claude hook bytes change, and 9 new files land in every no-flag install. **AD-2 — Codex hook command template.** Every `.codex/hooks.json` command is exactly:

```
R="$(git rev-parse --show-toplevel)" && CLAUDE_PROJECT_DIR="$R" exec "$R/.codex/hooks/<script>"[ --host codex]
```

- **What it does.** It resolves the root from the hook process cwd, which is the session cwd (H6), including from a subdirectory. It **overrides** a leaked `CLAUDE_PROJECT_DIR` (H13). It passes stdin, stderr and the exit code through (`exec`).
- **Why this form.** The command string is static, so the trust hash is stable across rooms (H3).
- **Why not the shim alone.** -11's shim adds robustness but cannot replace this export. Its branch order puts `CLAUDE_PROJECT_DIR` ahead of stdin `cwd`, so a leaked value would win.
- **Which hooks get `--host codex`:**
  - `pre-edit-gate.sh`, `pending-task-sentinel.sh`, `stamp-and-gate.sh` and `token-ledger.sh` get it.
  - `session-start.sh` gets none.
  - Outside a git repo, `git` fails, so the command exits non-2. That is fail-open (H9). ClearGate requires git.

**AD-5 — Install view per host set.** A new `src/lib/install-view.ts` provides the one function that turns a host set into a payload directory. It extends M3-A4 to every consumer:

