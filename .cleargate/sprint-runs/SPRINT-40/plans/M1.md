### 4.3 Change shape — `token-ledger.sh`

Replace the whole of `302-461` with a refusal. Decided shape:

```bash
  # --- resolve agent_type and work_item_id ---
  # BUG-069: attribution comes ONLY from a dispatch-time ground-truth source — the
  # CR-026 dispatch marker (read above) or the pending-task sentinel. When neither
  # supplied a value we REFUSE to attribute rather than infer one. A wrong
  # attribution is strictly worse than a missing one: it looks like data, and the
  # Reporter consumes it without suspicion. The prior-row inheritance this replaces
  # was self-referential — the fallback read its own last output, so the first wrong
  # value was copied into every subsequent row for the life of the sprint (101/101
  # rows in the observed field case).
  AGENT_TYPE="${SENTINEL_AGENT_TYPE}"
  WORK_ITEM_ID="${SENTINEL_WORK_ITEM_ID}"

  if [[ -z "${AGENT_TYPE}" ]]; then
    AGENT_TYPE="unattributed"
    printf '[%s] unattributed agent_type: no dispatch marker and no pending-task sentinel (session=%s sprint=%s)\n' \
      "$(date -u +%FT%TZ)" "${SESSION_ID}" "${SPRINT_ID}" >> "${HOOK_LOG}"
  fi

  if [[ -z "${WORK_ITEM_ID}" ]]; then
    WORK_ITEM_ID=""
    printf '[%s] unattributed work_item_id: no dispatch marker and no pending-task sentinel (session=%s sprint=%s)\n' \
      "$(date -u +%FT%TZ)" "${SESSION_ID}" "${SPRINT_ID}" >> "${HOOK_LOG}"
```

- **`WORK_ITEM_ID=""` is written explicitly** even though the variable is already empty. It is the
  contract, and it makes the branch self-documenting next to the `agent_type` assignment.
- **Log both refusals separately.** Task Breakdown row 2 requires the reason be visible in the hook

- **`SPRINT_ID` in the log line** dates the drift per sprint — the existing lines at `:116` and
  `:122` already carry it.

- **Update the header contract.** `:26-28` (*"If no sentinel exists: falls back to legacy

### 8.1 CORRECTION — the ALLOW_LIST gap does NOT produce `unattributed` rows

§3.5, §6 risk 3 and §7 open decision 1 all conclude that the six non-allow-listed agent roles will

So a `devops` dispatch gets no marker but **does** get a correctly-attributed sentinel, and post-069
its ledger row reads `agent_type: "devops"`, not `"unattributed"`. The ALLOW_LIST gap costs the

### 8.2 The refusal predicate must reject the literal `"unknown"`, not only the empty string

`pending-task-sentinel.sh:173` defaults `AGENT_TYPE` to the **literal string `"unknown"`**, not to
empty:

```bash
AGENT_TYPE="$(printf '%s' "${INPUT}" | jq -r '.tool_input.subagent_type // "unknown"')"
```

`IS_AGENT_SPAWN` is satisfied by `tool_name ∈ {Task, Agent}` alone, so a spawn carrying no
`subagent_type` writes a sentinel whose `agent_type` is `"unknown"` — non-empty. §4.3's
`if [[ -z "${AGENT_TYPE}" ]]` therefore never fires and the row ships `agent_type: "unknown"`
instead of `"unattributed"`: the exact fake-attribution BUG-069 exists to eliminate, surviving
through the one source §4.3 treats as unconditional ground truth.

**Decided replacement for §4.3's `agent_type` guard:**

```bash
if [[ -z "${AGENT_TYPE}" || "${AGENT_TYPE}" == "unknown" ]]; then
  AGENT_TYPE="unattributed"
  printf '[%s] unattributed agent_type: no dispatch marker and no usable pending-task sentinel (session=%s sprint=%s)\n' \
    "$(date -u +%FT%TZ)" "${SESSION_ID}" "${SPRINT_ID}" >> "${HOOK_LOG}"
fi
```

The `work_item_id` guard is **unchanged**: `pending-task-sentinel.sh:179` explicitly sets `""`, so
`-z` alone is sufficient there. Independent refusal (§4.3's first embedded decision) still holds.

This also removes the last producer of `"unknown"` — the other two sites (`token-ledger.sh:315`,
`:317`) are inside the deleted `302-461` region. Post-069 `by_agent.unknown` becomes an empty
bucket; `ledger-digest.mjs:16`'s "must not crash" contract still holds and needs no edit.

**Add a fifth red test to §4.5:** seed a `.pending-task-*.json` carrying `agent_type: "unknown"`
and a non-empty `work_item_id`; fire; assert the row is `agent_type == "unattributed"` while
`work_item_id` keeps the sentinel's value. Without it, a `-z`-only predicate scores identically to
a correct one.

### 8.4 The hook-level rename-proofing is unreachable through the settings.json route
