**Gotchas surfaced from code inspection:**
- Client code sits inside TS template literals (render.ts:985-1091). Never write `${` in client JS, and write escapes as `\\u…` the way the neighbouring lines do.
- New top-level client names must be `var` or `function`. vm harnesses reach `ctx.cgBacklogIsDone`, `ctx.cgBacklogStatusOk` and `ctx.cgBacklogState` only that way (M3 note).
- Add no `<script>` element (flashcard #dashboard #test-harness: cr102 reads the FIRST `<script>`, cr102.node.test.ts:343).
- Compare against the stored string, never `el.innerHTML`. `cgEsc` emits `&#39;` and `&quot;`, but a browser reads text back as `'` and `"`. A read-back compare would differ on every title that contains a quote, so every poll would rewrite the list again.
- Statuses that only children carry still come from `items`. Child items are top-level backlog items too (`byId` is built from `d.items`), so `uniq(items…)` already covers them.
