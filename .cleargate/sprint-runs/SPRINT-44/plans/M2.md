- **Sprint listing.** `fs.readdirSync(<cwd>/.cleargate/delivery/pending-sync)`, keeping names where `name.startsWith('SPRINT-') && name.endsWith('.md')`. The id is `idFromFilename(name)` (`src/lib/work-item-id.ts:220`); skip it when the result is null or `classifyType(id) !== 'SPRINT'` (`:120`). A missing directory yields `{ sprints: [], diagnostics: [] }`.
- **Exclusions.** These mirror 03's R4 refusals, so the picker never offers a sprint the handler refuses. Exclude when any of these holds:
  - `fm.status` is `'Active'`, `'Completed'` or `'Abandoned'` (Abandoned: Amendment §A2; picker-only, the handler still accepts an Abandoned target)
  - `id === resolveActiveSprint(cwd)?.sprintId` (`sprint-file-locate.ts:101`; called once per `collectPlan`)
  - `fs.existsSync(<cwd>/.cleargate/sprint-runs/<id>/state.json)`

  Verified: in this repo that leaves SPRINT-31/37/42/43. SPRINT-07/16/29 are `Abandoned` (SPRINT-16 also has a `state.json`) and SPRINT-44 is `Active` (Amendment §A2).

A throw (missing framing, malformed framing, bad YAML) skips that file and pushes one diagnostic, `plan: skipped <rel>: <message>`. Never treat a throw as "no frontmatter" (flashcard 2026-09-26 #frontmatter #locator #danger).
- **Lists.** For each of `epics|stories|bugs|crs|proposals`: `Array.isArray(fm[k]) ? fm[k].filter(x => typeof x === 'string' && x.trim() !== '').map(x => x.trim())`, otherwise `[]`. SPRINT-37 carries no lists at all, so a missing key is normal.
- **Title.** Take the first body line starting with `# `. Strip `# `; if the rest starts with `${id}:`, strip that too and trim. If there is no heading, use `''`.
- **`bodyOutOfDate`.** F = `stories ∪ bugs ∪ crs ∪ proposals` (**epics excluded**, see Open decision 2). T = `deliverablesTableIds(body)` minus ids where `classifyType(id) === 'EPIC'`. `bodyOutOfDate = F ≠ T` as sets.
- **`deliverablesTableIds(body)`.**
  - Split lines with `/\r?\n/`.
  - Find the first line matching `/^#{2,3}\s+(?:\d+\.\s*)?Consolidated Deliverables\b/i`. If there is none, return `[]`.
  - Scan forward, stopping at the next `/^#{1,2}\s/` heading, for the first line containing `|` whose next line is a separator row: every `splitTableRow` cell matches `/^:?-{2,}:?$/`.
  - **Id column by header name** (FLASHCARD 2026-07-14 / 2026-09-25 #dashboard). Normalise each header cell: lowercase, remove everything except `[a-z]`. The first cell whose result is in `{'storyid','id','item','workitem','story'}` is the id column; fall back to index 0. Verified real headers: `Story ID` (SPRINT-44, SPRINT-37, SPRINT-29), `ID` (SPRINT-42, SPRINT-43, SPRINT-31), `Item` (SPRINT-16).
  - Data rows run until the first line without `|` or the first all-empty row; skip separator rows.
  - Per row, the id is `extractWorkItemIds(cell.replace(/`/g, ''))[0]` (`work-item-id.ts:147`). Dedupe, keeping first-seen order.
- **`splitTableRow(line)`.** Trim. Drop one leading `|`. Drop one trailing `|` unless it is escaped (`\|`). Walk the characters: `\|` appends a literal `|` to the current cell, an unescaped `|` ends the cell. Trim every cell. **Do not reuse `collect.ts:250 splitRow`**: it splits on every `|` (flashcard 2026-09-25 #dashboard #sprint-plan), and collect.ts is out of 04's surface (Rule 2).
- **Candidates for sprint `s`**, from `backlog.items`:
  - Schedulable types: `{'epic','story','bug','cr','proposal'}`. Anything else (initiative, spike, hotfix, sprint) is never a candidate; 03 refuses those ids anyway.
  - `members` = the set of ids in the five lists.
  - Eligibility: `member || item.sprint === null || item.sprint === s.id || item.carryOver || stale` (R2), where `stale` = the item's claim names another sprint and `staleOf(claim) !== null` (Amendment §A1). The `member` clause is an Architect addition: a member whose item frontmatter has drifted must still appear pre-ticked so it can be removed.
  - Warnings, in this fixed order, with these exact strings:
    1. `not approved` when `!item.approved`
    2. when `item.gate.pass === false`: `fails ${item.gate.failing.join(', ')}`, or `gate failing` when `failing` is empty (`pass === null` produces no warning)
    3. `no stories in this sprint` when `item.type === 'epic'`, the item is in `s.epics`, and no id in `backlog.children[item.id] ?? []` is in `s.stories`

  - A member id that has no backlog item becomes a candidate `{ id, type: detectWorkItemType(id) (work-item-type.ts:61), title: '', member: true, disabled: false, otherSprint: null, warnings: ['not found in pending-sync'] }`.
  - Ordering: members first, then non-members. Within each group, sort by `a.id.localeCompare(b.id, 'en', { numeric: true })`.

## §A1 Stale-claim classification (R2 clarified)

**Rule.** A candidate row is disabled only when the item's `sprint_cleargate_id` names another sprint *and* that claim is **open**, in exactly the sense `cleargate sprint add` uses. A stale claim makes the row an enabled candidate, with a reassign warning.

**Source of truth.** `src/commands/sprint-scope.ts:436–456` (cli `main` `0e60fbd`), inside `sprintScopeHandler`. The check runs for `op === 'add'` when the claim is a non-empty string that differs from the target sprint, in this order:

1. If `findSprintPlanFile(cwd, claim) === null`, the handler warns `<ID> was claimed by <X> (no sprint file) — reassigned`.
2. Otherwise, if the claimed sprint's frontmatter has `status === 'Completed'`, it warns with `(completed)`. Unreadable frontmatter counts as status `undefined`.
3. Otherwise, if the path is under `<cwd>/.cleargate/delivery/archive/`, it warns with `(archived)`.
4. Otherwise it refuses: `<ID> is already in <X> — run \`cleargate sprint remove <X> <ID>\` first`. This is an open claim.

Status is tested before the path, so an archived sprint whose status is Completed reports `completed`. Every archived sprint claimed in this repo is in that state: SPRINT-01, 08, 14, 30, 32, 36, 39 and 41. Anything that steps 1–3 do not catch is open. That covers `Draft`, `Ready` and `Active`; **`Abandoned` sprints in pending-sync** (SPRINT-07, 16, 29); and a pending-sync sprint whose frontmatter cannot be read.

**Reuse decision: mirror the rule, do not import it.** The classification is written inline in the handler body and is not exported, so `plan.ts` has nothing to import. Exporting it would mean editing `sprint-scope.ts`, which is 03's merged file and outside 04's §3.1 surface. (Importing `sprint-scope.ts` from `plan.ts` would not create a cycle, since `serve.ts` already imports it.) Test E4 (§A4) keeps the mirror honest by running the real handler on the same tree. Removing the mirror is follow-up A-3.

  ```ts
  /**

   * the op === 'add' claim branch), in the same order: no plan file, then status Completed,
   * then a file under delivery/archive/. Returns null for an open claim (Draft, Ready,
   * Active, and Abandoned in pending-sync). plan-stale-claims.red E4 holds the two in parity.
   */
  function staleReason(cwd: string, claim: string, archiveDir: string): StaleReason | null {
    const p = findSprintPlanFile(cwd, claim);
    if (p === null) return 'no sprint file';
    let status: unknown;
    try {

    } catch {

    }
    if (status === 'Completed') return 'completed';
    if (p.startsWith(archiveDir)) return 'archived';
    return null;
  }
  ```
