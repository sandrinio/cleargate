## Cross-Cutting Rules

Sprint-wide architecture rules every story must honour. Derived from the M1 items' shared concerns (init.ts surface ownership, three-site dogfood-mirror discipline, identity/membership state-machine invariants, schema-version stability, pre-member default) plus M2 extensions (vocabulary-purge grep gates, protocol §-numbering, autonomy-hook settings schema, schema-v3 migrator safety against SPRINT-28 archive).

1. **`cleargate-cli/src/commands/init.ts` is a shared surface this milestone.** Three M1 stories edit it (STORY-068-01 line 452, STORY-069-01 post-Done banner, BUG-031 identity/state resolver). Merge order is fixed: STORY-068-01 → STORY-069-01 → BUG-031. Do not parallel-merge — sequential serialization is mandatory because the file is small and rebases are cheap.
2. **Three-site dogfood-mirror discipline applies to every payload edit.** Canonical (`cleargate-planning/.gitignore`, `cleargate-planning/CLAUDE.md`, `cleargate-planning/.claude/**`) → npm payload (`cleargate-cli/templates/cleargate-planning/**`, regenerated by `npm run prebuild`) → live `/.claude/` (gitignored, hand-port or `cleargate init` against meta-repo). STORY-072-01 is the M1 story that flexes this rule; STORY-070-01 (CLAUDE.md edit) and STORY-071-01 (agents + skill + new hook + settings.json) both deeply flex it in M2. Forgetting any leg leaves a stale install or stale agent runtime.
3. **Identity is global; project_id is per-repo.** Per CR-011 + BUG-031 fix: participant email may be inferred from git config user.email globally, but `~/.cleargate/auth.json` membership tokens must NOT cause a fresh repo to report `state: member`. Fresh repo with no per-repo join → `state: pre-member` regardless of global token presence. The fix discriminator is the WORKING DIRECTORY, not the host.
4. **Tests touch real processes, real tmpdirs, real `git init`.** Every story whose acceptance Gherkin says "fresh repo" or "fresh tmpdir" must drive its tests via `node:child_process.spawnSync` against a `mkdtempSync` fixture that has been `git init -b main`'d. No mocked `fs`, no mocked spawn. Per global policy (CLAUDE.md "Real infra, no mocks"). M2's hook test (STORY-071-01) also follows this: shell script invoked via spawnSync against tmpdir-fixture `.cleargate/sprint-runs/.active` + `state.json`.
5. **node:test only. File naming `*.node.test.ts`.** Per EPIC-028 closure 2026-05-18 — vitest is eliminated. New tests use `tsx --test` runner. Existing init test file is `cleargate-cli/test/commands/init.node.test.ts` (already correctly named). M2 adds: `cleargate-cli/test/util/gate-mode.red.node.test.ts`, `cleargate-cli/test/scripts/migrate-schema-v3.red.node.test.ts`, `cleargate-cli/test/docs/no-execution-mode-vocabulary.red.node.test.ts`, `cleargate-cli/test/integration/advisory-env-gate.red.node.test.ts`, `cleargate-cli/test/hooks/pre-tool-use-autonomy.red.node.test.ts`, `cleargate-cli/test/docs/autonomy-contract.red.node.test.ts`. All `*.red.node.test.ts` per CR-043 immutability.
6. **Readiness-gate path-extractor regex tightens mid-sprint (STORY-073-01).** Stories merged AFTER STORY-073-01 lands MUST cite §Existing Surfaces paths with at least one `/` separator; root-level files use `./CLAUDE.md` form. Stories merged BEFORE STORY-073-01 land under the permissive rule. M1 wave plan lands STORY-073-01 in Wave 0 to neutralize this drift across the rest of M1 and ALL of M2.
7. **(M2 extension) Schema-v3 migrator must not corrupt SPRINT-28's archived state.json.** Live `.cleargate/sprint-runs/SPRINT-28/state.json` carries `schema_version: 2` + `execution_mode: "v2"`. STORY-070-01's migrator MUST be fixture-tested against a copy BEFORE running against the live file. Migrator contract: strip `execution_mode` + bump `schema_version` to 3; preserve all other fields byte-identical (JSON.stringify with 2-space indent + trailing newline to match conventional format).
8. **(M2 extension) Protocol doc §-numbering audit.** Current max `## N.` heading in `.cleargate/knowledge/cleargate-protocol.md` is **§21 Status Vocabulary** (line 618). STORY-071-01's new section gets **§22 Sprint Execution Autonomy**. Cross-references from agent .md files MUST use the section-NAME (`§ Sprint Execution Autonomy`) not the number (`§22`) — future renumbering doesn't break name-based references. Verified via `grep '^## [0-9]' .cleargate/knowledge/cleargate-protocol.md | sort -n -k2 | tail -1`.
9. **(M2 extension) CLAUDE.md edits land sequentially in canonical order.** STORY-070-01 deletes the `**Sprint mode.**` paragraph from `cleargate-planning/CLAUDE.md` line 30 BEFORE STORY-071-01 ships. If 071 chooses to add a cross-reference to §22 from CLAUDE.md, that addition lands AFTER 070's deletion. Enforced by wave order: M2 Wave 4 is STORY-070-01 → STORY-071-01 strictly sequential.
10. **(M2 extension) Agent definitions span 5 files for CR-071.** `cleargate-planning/.claude/agents/{architect,developer,qa,devops,reporter}.md` ALL gain an `Autonomy Contract` subsection from STORY-071-01. Test asserts presence on each — missing-on-any-one fails. NPM payload mirrors all 5 via `npm run prebuild`. Live `/.claude/agents/` re-syncs via `cleargate init` re-run as M2 closing-act gate.
11. **(M2 extension) Grep-gate `check:no-execution-mode-vocabulary` exclusions.** STORY-070-01's npm script must exclude `archive/`, `node_modules/`, `test/`, `sprint-runs/`, and `package.json` itself (script body contains the regex patterns). Otherwise false-positives on the script's own test file and the script's package.json entry.
