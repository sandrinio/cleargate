**C1 — STORY-063-01 (`cleargate-cli/src/lib/wiki/contradict.ts`)**

C1.1 `export function contradictContentHash(raw: string): string`
- Computes `createHash('sha256').update(body, 'utf8').digest('hex')`. The result is lowercase, 64 chars, with no prefix.
- `body` is defined as follows:
  - `body = raw.slice(span.end)` where `span = locateFrontmatter(raw)` (`src/lib/frontmatter-locator.ts:69`).
  - `span.end` is the offset right after the closing `---` text, so that line's EOL is the first byte of `body`.
  - Everything before `span.start` (the `<instructions>` preamble, BOM) is excluded.
  - `span === null` → hash the whole `raw`.
  - If `locateFrontmatter` throws, the error propagates (callers decide).
- No CRLF normalization, no trimming. This exact definition is what 07 re-implements in plain Node and pins with a known-value fixture.

C1.2 `export function phase4SkipReason(fm: Record<string, unknown>): string | null`
- Returns `` `status=${s}` `` when `String(fm.status ?? '')` ∉ `PHASE4_TRIGGER_STATUSES` (`contradict.ts:28`).
- Else returns `'approved=true'` when `fm.approved === true`.
- Else returns `null`.
- `preparePhase4` calls it first (it replaces `contradict.ts:87-91`).

C1.3 `export function parseFindings(input: string): ContradictFinding[]`
- Throws `Error` with a message naming the problem. Never partially returns.
- `draft` is `''` when the input omits it. `commitPhase4Findings` already falls back to `draftId` (`contradict.ts:168`).

C1.4 `export function collectNeighborhood(opts: { fm; body; wikiRoot }): string[]`
- Today it is a private function (`contradict.ts:331`); make it exported, with no behaviour change.
- The commit handler uses it to compute `truncated`.

2. `parseFindings` rules:
   - **JSON first:** `JSON.parse(input.trim())` succeeds → the value must be an array.
     - Each entry must be an object with non-empty string `neighbor` and `claim`. `draft` is optional; when present it must be a string.
     - Otherwise throw naming the entry index and the field: `"entry 1: missing claim"`.
   - **Otherwise, text mode:**
     - Finding lines match `/^contradiction:\s+(\S+)\s+vs\s+(\S+)\s+·\s+(.+)$/` (U+00B7 middle dot). This is not an ID-escape regex, so it does not trip `scripts/check-no-inline-id-regex.mjs`. Do not add `EPIC-\d`-style patterns anywhere in `src/`. Use `src/lib/work-item-id.ts` helpers if an ID must be validated.
     - The summary line matches `/^contradiction-check:\s+(no findings|(\d+) finding\(s\) emitted)\s*$/`.
     - Every other line (the `role:` line, reasoning paragraphs) is ignored.
     - Valid text input has ≥1 finding line or a summary line. Neither → throw `"input is neither a JSON findings array nor cleargate-wiki-contradict output"`.
     - Summary count ≠ parsed finding count → throw `"summary reports N finding(s) but M contradiction lines were parsed"` (all-or-nothing against a truncated paste).
   - Strip `[[`/`]]` from `draft` and `neighbor` in both modes. `commitPhase4Findings` re-wraps at `contradict.ts:168-169`; without the strip you get `[[[[EPIC-Y]]]]`.
   - Claim length is NOT enforced (an 81-char claim must not discard a whole real check). Do not mutate claims.
   - Empty input → throw.
3. `wikiContradictCommitHandler` (C1.6). Validate everything before any write (R3):
   - Raw file exists.
   - `deriveBucket(basename)` succeeds.
   - Raw frontmatter locatable (`locateFrontmatter` non-null; otherwise `stampContradictSha` would silently no-op, `contradict.ts:484-492`).
   - Wiki page `.cleargate/wiki/<bucket>/<id>.md` exists and `parsePage` succeeds. If not → exit 1 `"wiki page not found for <ID> — run cleargate wiki ingest <raw> first"`.

## BUG-086 check (STORY-063-03 vs "DevOps merges fail on orchestrator wiki dirt")

**During M1:** no effect.
- All M1 merges are in the cleargate-cli repo, which has no `.cleargate/wiki/`.
- The new hook is not live until the release re-sync.
- The outer-repo commits in M1 (CR-126's EPIC-063 reshape, 07's procedure doc) are plain commits, not merges, so wiki dirt cannot abort them.
- **DevOps rule for M1 outer commits:** stage by explicit path (`git add <file>`), never `git add -A` or anything under `.cleargate/wiki/`. The outer wiki is dirty right now (git status shows 6 wiki files modified).

**After 0.29.0 is live in this repo (SPRINT-42 onward): yes, it gets worse.**
- Today, main-checkout wiki dirt comes only from the orchestrator's own Edit/Write.
- With 03, every DevOps `git merge` that brings in a delivery-file change moves HEAD. The very next Bash call ingests those files and rewrites `wiki/index.md`, `log.md` and synthesis pages.
- So the main checkout is guaranteed dirty after each story merge.
- If the next story branch also carries wiki changes (worktree ingest writes the worktree's own wiki; CR-093 "file owns root"), that merge aborts exactly as BUG-086 describes.
- BUG-086's proposed fix (stash `.cleargate/wiki/` in DevOps step 2, merge, `stash pop`) also breaks under 03:
  - The merge's own Bash call fires the hook, which re-dirties `index.md`/`log.md` before the pop.
  - `git stash pop` then refuses ("local changes would be overwritten") and leaves a stash behind.

What 03 does about it (built in, above):
- (a) Skip ingest while `MERGE_HEAD`/rebase state exists, so conflicted files are never parsed and no wiki writes happen mid-merge.
- (b) The freshness dedup (G3), so an unrelated Bash call never rewrites pages that are already current.
- (c) A `mkdir` lock against concurrent `log.md` appends.

What DevOps should do (recommendation for the BUG-086 owner; not M1 scope):
- Replace stash/pop with **commit-before-merge**.
  - Add `.cleargate/wiki/**` to `surface-whitelist.txt`. This is BUG-086's own first row.
  - DevOps step 2: when `git status --porcelain -- .cleargate/wiki/` is non-empty, run `git add .cleargate/wiki && git commit -m "chore(wiki): sync derived pages"`, then merge.
- On a `log.md` conflict, keep both blocks (flashcard 2026-09-25 `#merge #wiki`).
- **Schedule BUG-086 before any sprint runs on 0.29.0 live hooks.** SPRINT-42 is planned next and BUG-086 sits in SPRINT-43, so SPRINT-42 would hit the worsened behaviour. Pull BUG-086 into SPRINT-42, or ship it first.
