**08 vs 13: why 13 lands first.**
1. **Golden churn.** 08's tests are full-body goldens per type (EPIC-058, SPRINT-44 plan + report, a bug, a CR). If 08 lands first, its goldens freeze today's `## Blast radius / Affects:` block. 13 then replaces that block, so every sealed 08 golden would have to be re-sealed inside 13's commit. If 13 lands first, its tests assert relation frontmatter and the marker-delimited relations block (substring and parse checks, no full-body goldens), and 08 seals its goldens once, against the final page shape.
2. **Plumbing before content.** 13 restructures the data flow in `wiki-build.ts`/`wiki-ingest.ts`: one corpus scan, a relations map threaded into both writers, neighbour rewrites. 08 then only changes the content side of `buildPageBody` plus the `type`/report arguments its callers pass. 3. **Neighbour rewrites are content-agnostic.** 13 splices the relations block between markers (C13.4), so 08's later content rewrite cannot break it. 08 only has to keep the block's position (after the extract, before the sprint-report block), which C8.1 pins.
4. **The dependency graph does not care.** 09 needs both, and 10 needs only 08, so 13 → 08 → 09 → 10 costs nothing in latency over 08 → 13.

## Cross-item contracts (frozen exports; later items consume exactly these names)

Purity rule (supersedes M1 C4.1's "page-schema.ts has no imports"): `page-schema.ts`, `extract-sections.ts` and `relations.ts` stay **pure**: no `node:fs`, `node:child_process` or other I/O imports. `page-schema.ts` may import the other two (pure) modules. `extract-sections.ts` imports `page-schema.ts` for types only (`import type`), so there is no runtime cycle.

### C13 — STORY-063-13 (`src/wiki/relations.ts`, `src/wiki/page-schema.ts`)

C13.1 `src/wiki/relations.ts` (new, pure; imports `src/lib/work-item-id.ts` and `import type { RawItem }` only):
```ts
export interface ItemRelations {
  parent: string | null;      // bare ID, e.g. "EPIC-063"; null = no parent
  parentFound: boolean;       // parent resolves to a raw item (by id or alias)
  children: string[];         // bare IDs, C order, unique
  cites: string[];            // bare IDs, C order, unique, self excluded
  citedBy: string[];          // bare IDs, C order, unique
}
export type RelationsMap = ReadonlyMap<string, ItemRelations>;
export const EMPTY_RELATIONS: ItemRelations;          // { parent:null, parentFound:false, children:[], cites:[], citedBy:[] }
export const RELATIONS_LIST_CAP = 20;
export function parentIdOf(fm: Record<string, unknown>): string | null;
export function computeRelations(items: ReadonlyArray<Pick<RawItem, 'id' | 'fm' | 'body' | 'absPath'>>): Map<string, ItemRelations>;
```
- `parentIdOf`:
  - Take the first key of `parent_ref`, `parent_epic_ref`, `parent` whose value is a non-null, non-empty string after trimming.
  - If that value contains `NNN`, `|` or `{` → `null` (R1 placeholder rule). Do not fall through to the next key.
  - Strip a leading `[[`, a trailing `]]` and quotes.
  - `id = extractWorkItemIds(value)[0]` (`work-item-id.ts:147`). Return `id` only when the stripped value **starts with** that id; otherwise return `null` (G-M2-7).
- `computeRelations` input is the **unfiltered** `scanRawItems` result (stories included).
  - Known IDs are the set of `item.id` values.
  - **Alias map** (G-M2-10): for every item where `idFromFilename(basename(absPath))` (`work-item-id.ts:220`) is non-null and differs from `item.id`, map the short ID to `item.id`. Covers legacy hyphen-slug files such as `CR-083-Document-…`.
  - `cites`: every `[[X]]` in `item.body` (matched with `/\[\[([^\]\n]+)\]\]/g`, which is not an ID-shape regex), with X trimmed. Resolve X to an `item.id` directly, else through the alias map. Drop unresolved X and self.
  - `children` of P = every item whose `parentIdOf` resolves (id or alias) to P. Stories are included.
  - `citedBy` is the inverse of `cites`.
  - An entry exists for every item id, and also for any unresolved parent id that has children, so a report-only sprint page can still list them.

C8.2 `export function findSection(body: string, namePattern: RegExp): string | null`
- Scans ATX headings (`##`–`######`) outside fenced code blocks.
- Strips a leading number (`1.`, `0.5`, `§1`, `1.4`) from the heading text, then tests `namePattern` case-insensitively.
- Returns the text up to the next heading of the same or higher level, excluding the heading line itself. Blockquote guidance lines (`>`) are dropped. Returns `null` when the section is absent or empty.
- This generalizes `extractOpenQuestions` (`page-schema.ts:279-306`), which is deleted.

C8.4 Decision pairing, shared by 08, 10 and 11:
```ts
export interface DecisionPair { question: string | null; answer: string | null; resolved: boolean; line: number }
export function extractDecisionPairs(sectionText: string): DecisionPair[];
export function isPlaceholderAnswer(answer: string | null): boolean;
```
- Question bullets match `- **AI Question…:**` or `- **Question:**`.
- Answer bullets match `- **Human Answer:**` or `- **Human decision:**`.
- `- **Recommended:**` bullets and prose lines are skipped.
- An answer's text is the rest of its bullet line plus any following non-blank, non-bullet continuation lines.
- A question opens a pair and the next answer closes it. An answer with no open question becomes `question: null`. A question with no answer before the next question or the section end becomes `answer: null, resolved: false`.
- `isPlaceholderAnswer` is true for `null`, empty, text starting with `Unresolved`, or exactly `{populated during Brief review}`.
