### BUG-122 — init and upgrade record the same install state (U2, commit 1)
- **G-R-2: the hooks-only settings hash.**
  - **Function.** Add `export const CLAUDE_SETTINGS_PATH = '.claude/settings.json'` and `export function clearGateHooksProjection(text: string): string | null` to `src/lib/settings-json-surgery.ts`.
  - **What it hashes.** It parses the text and collects one triple `JSON.stringify([event, matcher ?? '', command])` per inner hook whose `command` passes `isClearGateCommand` (:53-56). It then dedups, sorts in C order (`a < b ? -1 : a > b ? 1 : 0`, never `localeCompare`), and returns `triples.join('\n') + '\n'`. It returns `null` on a JSON parse failure.
  - **What it ignores.** `type`, `if`, `timeout` and entry-level keys. This is the same `(event, matcher, command)` triple `verify-install.ts:207-229` `extractTriples` uses.
  - **Scope.** `.claude/settings.json` only. `.codex/hooks.json` keeps its raw hash.
- **G-R-3: one hash space.** The package, install and current hashes must agree.
  - `src/lib/manifest.ts` `computeCurrentSha` (:298-314): for `file.path === CLAUDE_SETTINGS_PATH`, return `hashNormalized(projection)` when the projection is non-null, else today's raw hash.
  - `src/lib/manifest-builder.ts` `walkDir` (:594-598): for `normalizedRelPath === CLAUDE_SETTINGS_PATH`, hash the projection of the file instead of the raw bytes. This makes `MANIFEST.json`, the composed payload and every `buildInstallView` (test fixtures) carry the projection hash, so `init`'s "records the package sha" automatically records it.
- **G-R-4: snapshots older than 0.30.1 hold a raw hash.** Add `export async function effectiveInstallSha(entry, installSha, projectRoot): Promise<string | null>` to `manifest.ts`.

### BUG-120 — no-terminal upgrade finishes or refuses (U2, commit 2)
- **G-R-8: when stdin counts as interactive.** Add the seam `stdinIsTTY?: boolean` to `UpgradeCliOptions`, mirroring `init.ts:739`.
  - Rule: `interactive = cli.stdinIsTTY ?? (cli.promptMergeChoice !== undefined || ((cli.stdin ?? process.stdin) as { isTTY?: boolean }).isTTY === true)`.
  - An injected prompt counts as interactive, which keeps every existing prompt-seam test green: `upgrade.node.test.ts:309-491`, `upgrade-restart-warning.red`, `upgrade-state-parity.red`, `upgrade-pin-and-prune.node.test.ts:197`.
- **G-R-9: which merge-3way files are asked about.** Restructure the front of `applyMerge3Way` (:365-384):
  1. **Already equal to upstream** (`currentSha !== null && currentSha === entry.sha256`): no write and no output line. The snapshot entry is set to `entry.sha256` when it differs. Return.
  2. **`upstream-changed` or `untracked`** (missing locally): take theirs through the same adapter surgery path (:393-414) without a prompt. After a successful write, print one line `[take] <path>  state=<state> (unchanged locally)`, or `(missing locally)` for untracked, in place of the plain `[take] <path>`. The `state=` token keeps BUG-028's parity test (`upgrade-state-parity.red.node.test.ts:244-268`) meaningful.
  3. **`--yes`:** today's `[yes] taking theirs:` line, then take.
  4. **Otherwise** (`user-modified`, `both-changed`): prompt.
- **G-R-10: refuse before writing anything.** Place the check directly after the dry-run block (:736) and before step 5.
  - `wouldPrompt` = merge-3way `workItems` that land in branch 4.
  - If `!flags.yes && !interactive && wouldPrompt.length > 0`, print to stderr:
    - the recorded text verbatim: `upgrade needs a terminal to ask about N file(s); re-run with --yes to take upstream for them, or run it in a terminal`;
    - then one `  <path>  state=<state>` line per file.
  - Then `view?.dispose(); view = undefined; exit(2); return;`. A real `process.exit` skips the `finally` at :976, so dispose first.
  - `--dry-run` never refuses.
- **G-R-11: the prompt settles at end of input.** Changes to `promptMergeChoice` (`src/lib/merge-ui.ts:80-107`):
  - **Settle on end.** Also listen for `end` and `close`, and reject with `export class MergePromptClosedError extends Error`. If the stream is already `readableEnded` or `destroyed` on entry, reject immediately.
  - **A partial line is not an answer.** Buffered text without a newline at end-of-input is not an answer.
  - **Carry leftover bytes.** Bytes after the first newline are kept per stream in a module-level `WeakMap<NodeJS.ReadableStream, string>`; the next prompt reads them first (today `"t\nk\n"` in one chunk loses the second answer).
  - **Pause.** Call `stdin.pause()` after settling, and `resume()` after attaching.
- **G-R-12: input ends mid-run.**
  - Every handler (`applyAlwaysOverwrite`, `applyPinAware`, `applyMerge3Way`) reports whether it wrote, and the loop collects `written: string[]`.
  - Wrap the per-file switch. On `MergePromptClosedError`, print to stderr:
    - `upgrade stopped: input ended while asking about <path>; nothing more was written.`;
    - `files already written (<k>):` plus one `  <p>` line each;
