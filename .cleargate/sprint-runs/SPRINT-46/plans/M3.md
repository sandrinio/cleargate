**Runner contract (`wave_runner.js`, pinned).**
- Line 1 is the only export: `export const meta = { name: 'cleargate-wave-runner', description, phases: [Plan, QA-Red, Wiring, Build, Verify, Post-flight] }`, each phase as `{ title }`.
- Workflow globals only (`agent`, `parallel`, `log`, `args`); no `import`, `require`, `process` or `fs`. Start with `const A = typeof args === 'string' ? JSON.parse(args) : args`, because SPRINT-36's `story-loop.mjs:13-16` received string args.
- No lane-name literal, no array literal holding two stage names, no `BOUNCE_CAP`, `max_parallel` or `concurrency`. The cap is `A.bounceCap`.
- One adapters table at the top, keyed by stage name. It is presentation and I/O only; which stages run comes from `item.stages`. Every schema also has an optional `flashcards_flagged: string[]`, and `required` lists the first field only.

  | stage | phase | label | role | schema |
  |---|---|---|---|---|
  | story-plan | Plan | Architect | plan | `{ ok: boolean, path }` |
  | qa-red | QA-Red | QA-Red | red | `{ status: WRITTEN\|BLOCKED, sealed_sha, scan_exit: number, flags: string[], tests, scenarios, spec_gap }` |
  | architect-tpv | Wiring | Architect | red-check | `{ result: APPROVED\|BLOCKED-WIRING-GAP\|PASS\|FAIL, issue }` |
  | developer | Build | Developer | build | `{ status: done\|blocked, commit, blocker_section: none\|Test-Pattern\|Spec-Gap\|Environment, notes }` |
  | qa-verify | Verify | QA-Verify | verify | `{ result: PASS\|PASS-PENDING-SMOKE\|FAIL, defect_in: none\|code\|red-test\|spec, defects: string[], commands_run: string[], proof: pass\|fail\|n/a }` |
  | architect-review | Post-flight | Architect | build-check | same as architect-tpv |

- Helpers: `scanFlagged(red)` is true when `red` is missing, `scan_exit !== 0`, or `flags` is non-empty (C-4). `defectIn(v)` returns `v.defect_in` when it is `code`, `red-test` or `spec`, else `'code'`. `tierUp`: haiku→sonnet, sonnet→opus, opus→opus.
- **Dispatch.** `agent(prompt, { label, phase, agentType: stage.agent, schema, ...(model ? { model } : {}) })`. The description is `${label} ${id}`, with ` pass ${n}` added on the n-th dispatch of that stage (n > 1); this is the `label` option (C-1). Developer model: `tierUp(models.developer ?? 'sonnet')` when `cycle === A.bounceCap && A.bounceCap > 1`, else `models.developer`. Other stages use `models[stage.name]`.
- **Prompt.**
  - Line 1 is the label, then: `Sprint <sprintId>. Item <id> (lane <lane>). Item file: <file | "find <id>_*.md under .cleargate/delivery/">. Worktree: .worktrees/<id> (branch story/<id>, base <base>). Read .cleargate/sprint-runs/<sprintId>/sprint-context.md first.` Add `Mode: <stage.mode>` when the stage has one.
  - red: end with `seal_red.mjs … --sprint-branch <base>` per qa.md Mode: RED, and return its JSON fields plus `status`.
  - build: the plan input is `plans/<id>.md` when the lane has a plan stage, else sprint plan §2 and the `waves.json` contracts. On rework, add the last `defects`/`issue`.
  - red-check: `reports/<id>-pre-arch-scan.txt` and `flags`.
  - plan: write `plans/<id>.md`, at most 150 lines.
  - Never write `approved`, `confirmed` or `authori[sz]ed` (W009-7).
- **Walk** `item.stages`: a `barrier-script` stage ends the walk; a stage with no adapter row → BLOCKED; a `scan-flagged` stage is skipped unless `scanFlagged(lastRed)`; otherwise dispatch it and push its name to `stagesRun`. A null result or a throw → BLOCKED `technical-impossibility` naming the stage.

| role | on pass | on fail (cap = `A.bounceCap`; ESCALATED blocker type per C-6) |
|---|---|---|
| plan | `ok` → next | BLOCKED `technical-impossibility` |
| red | WRITTEN with a non-empty `sealed_sha`: set `lastRed`, `qaSha`; next | BLOCKED → BLOCKED `spec-contradiction` (`spec_gap`); WRITTEN without a sha → BLOCKED `technical-impossibility` |
| red-check | APPROVED/PASS → next | `arch_bounces++`; at cap ESCALATED, else rewind to red |
| build | `done` with a commit: set `devSha`; next | `blocked` → BLOCKED: `spec-contradiction` for Spec-Gap, else `technical-impossibility` |
| verify | PASS or PASS-PENDING-SMOKE → next | `qa_bounces++`; push `defectIn` to `defects_in`. Then: `spec` → BLOCKED `spec-contradiction`, no further dispatch; at cap → ESCALATED; `red-test` → rewind to red; else rewind to build |
| build-check | PASS → next | `arch_bounces++`; at cap ESCALATED, else rewind to build |

- **Verdict**: `{ verdict, storyId, runId, devSha, qaSha, flashcards_flagged, counters: { qa_bounces, arch_bounces, breaker_hits: 0 }, tokens: { metering: 'unavailable' }, lane, stages_run, defects_in, blocker? }`.
  - GREEN needs `devSha`, and needs `qaSha` unless the lane has no red stage (then `qaSha` is `null`). A non-GREEN verdict sets any missing SHA to `null`.
  - `flashcards_flagged` is the ordered, de-duplicated union.
  - Each segment is wrapped in try/catch (a throw becomes BLOCKED), so `parallel()` never rejects.
- **Top level.** `ready` = the items whose upstream ids are all in `A.merged`. `waiting` = the rest, each as `{ storyId, needs }`. `return { verdicts: await parallel(ready.map((it) => () => segment(it))), waiting }`.
