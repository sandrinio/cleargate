**Helper contract** (pin exactly; QA-Red and the Developer read the same text)
- `resolve_check_target <wt> <cmd>`
  - Prints the dir from a literal `--prefix <dir>` token, or from a leading `cd <dir> &&`. Otherwise it prints nothing.
  - It also prints nothing when `<dir>` is absolute or contains `$`, a quote or a backslash (C-4). The command then runs, so a bad guess becomes a visible FAIL, never a silent N/A.
- `run_configured_check <report> <name> <cmd> <wt>` returns 0 (pass), 1 (fail) or 3 (N/A). It applies these rules in order:
  1. Empty cmd → `[INFO] <name>: not configured`.
  2. Target dir missing → `[N/A] <name>: target <dir> is not in the worktree`.
  3. `<wt>` is not a dir → `[FAIL] <name>: worktree <wt> is not a directory`.
  4. Otherwise run `out=$( ( set +e +u +o pipefail; cd "$wt" && eval "$cmd" ) 2>&1 ) || rc=$?`. The command gets host shell semantics, not the scan's `-euo pipefail` (C-5). Declare `local out rc=0` on a separate line before the assignment, or `local` masks the exit code.
  5. On pass → `[PASS] <name>: <cmd>`.
  6. On fail → `[FAIL] <name>: exit code N`, then `printf '%s\n' "$out" | tail -n 40 | sed 's/^/  | /' >> report`.
- Callers must write `rc=0; run_configured_check ... || rc=$?; [[ $rc -eq 1 ]] && OVERALL_EXIT=1`. A bare call returning 1 or 3 kills the script under `set -e`.
- The `  | ` prefix keeps tail lines out of `print_summary`'s `^\[FAIL\]` count and out of the CR-120 extractor's `^\[(FAIL|WARN)\]` match (:390), so no extractor edit is needed.

**record_baseline.mjs behaviour**
- **Root and paths:** `REPO_ROOT = CLEARGATE_REPO_ROOT ?? <script>/../..` (as in `init_sprint.mjs:37-39`). `sprintDir = REPO_ROOT/.cleargate/sprint-runs/<id>` (`init_sprint.mjs:144`); `mkdir -p` it.
- **Config:** `REPO_ROOT/.cleargate/scripts/gate-checks.json`. Missing or unparsable → `baseline: skipped — gate-checks.json not found` and exit 0.
- **Command choice:** `qa.baseline_command` if it is a non-empty string, else `qa.test`. Both empty → `baseline: skipped — qa.test and qa.baseline_command are empty`, nothing written.
- **Run:**
  - Print `recording baseline: <cmd>`.
  - `spawnSync('bash',['-c',cmd],{cwd:REPO_ROOT,encoding:'utf8',timeout:1_200_000,maxBuffer:64*1024*1024})`.
  - `output = [stdout, stderr].filter(Boolean).join('\n')`, so stderr comes last and the shell's "not found" line lands in the tail.
- **Exit-code mapping:**
  - `error.code === 'ETIMEDOUT'` → 124, with a last tail line `baseline: command timed out after 20 minutes`.
  - Any other `error` → 127, with the message as the last tail line.
  - Otherwise `status`.
  - The tail is at most 40 lines in total, including the reason line.
- **Fields:**
  - `base_sha` = `git -C REPO_ROOT rev-parse HEAD`, or `'unknown'`.
  - `failing` = `exit_code === 0 ? [] : extractFailing(output)`.
- **Write and report:** write atomically (`<file>.tmp.<pid>` then `renameSync`) and print `baseline: <n> failing (exit <code>) -> <path>`.

**`extractFailing(output)` (sync; returns sorted, de-duplicated identifiers)**
- TAP `^\s*not ok \d+ - (.+?)(\s+#\s+(TODO|SKIP)\b.*)?$` → the name. TODO-directive lines are skipped.
- Spec reporter `^\s*✖ (.+?)(\s+\(\d+(\.\d+)?m?s\))?$` → the name, excluding the literal `failing tests:`.
- `^\s*test at (\S+:\d+:\d+)$` → the `file:line:col` string. It is relative under node:test (verified on Node 25: `test at test/b.test.mjs:1:1`).
- Go `^\s*--- FAIL: (\S+)` → the test name, including subtests like `TestA/sub`.
- Go `^FAIL\t(\S+)` → the package. A bare `FAIL` line is ignored.
