## Decisions (this plan governs; for the orchestrator to ratify as CR:spec-clarifications)
- **D-1 Detecting an earlier merge needs both checks.** A re-run resumes only when the sprint branch's first-parent line has a merge commit whose subject starts with `merge(story/<ID>):` (the subject `merge_story.mjs:366` writes) **and** whose second parent is the tip of `story/<ID>`. Checking the parent alone would mark `Done` a branch with no work that was cut from another story's merged tip, which is the §1.5 risk. Checking the subject alone cannot tell which tip was merged. This is stricter than R3's wording (parent only) and is pinned by I5.
- **D-2 The story branch is gone.** If `story/<ID>` does not exist and the subject-only match (D-1 without a tip) finds a merge commit, the run resumes: it removes the worktree when its directory exists, skips the branch delete, and updates state. A run that fails at `state` has already deleted the branch, and R2's tail line tells the orchestrator to re-run, so this case has to resume. With no such commit the result is today's `branch story/<ID> does not exist`. Pinned by I7 (resume) and I5 (refusal).
- **D-3 The worktree directory is gone.** If `.worktrees/<ID>` no longer exists, run `git worktree prune` and skip removal. Checked on git 2.50.1: a deleted worktree directory that is still registered makes `git branch -d/-D` fail with "cannot delete branch … used by worktree", and `prune` clears it. Pinned by I3.
- **D-4 A resumed run deletes the branch with `git branch -D`.** During a re-run the main checkout may be on another branch, and `-d` would then refuse a branch that is not merged into HEAD. D-1 has already proved the tip is the second parent of a merge commit on the sprint branch. A fresh merge keeps `-d`.
- **D-5 What a resumed run skips:** the MERGE_HEAD check, the check that the worktree exists, both dirt checks, the scan, the merge, the prebuild and the post-merge test. The teardown residue check (`:419-421`) still runs, so real uncommitted work in the worktree gives a `teardown` exit 2. A resumed run always calls `update_state.mjs <ID> Done`. That call is a no-op exit 0 when the item is already `Done` (`update_state.mjs:441-445`), so re-running a finished merge also exits 0.
- **D-6 How R2 works.** Teardown and state move into a `finish()` closure inside `mergeStory`. The closure holds a `step` variable and a try/catch, and both a fresh merge and a resumed one call it. Every non-zero result from `finish`, whether a handled git or `update_state` failure or a thrown error, ends its tail with the landed line. `main`'s catch does not change: no exception after the merge reaches it, so it still labels pre-merge errors `precondition`.
- **D-7** The landed line adds ` --worktree <path>` after `--sprint <SPRINT-ID>` only when `--worktree` was given. Without the flag the text matches R2 word for word.
- **D-8** Two paths stay as they are: the `crash:` path with step `merge` (`:410-412`) and the write-back failure path (`:405-408`). The merge/build/test block calls only `spawnSync` helpers, which do not throw.

This is the recovery path that §1.3 says the skill names. 3. **New helper.** Add after `readJson` (`:196-198`):
```js
/**
 * The newest merge commit on the first-parent line of `sprintBranch` whose subject starts with
 * `merge(story/<id>):` (the subject this script writes) and, when `tip` is given, whose second
 * parent is `tip`. Returns its SHA, or null.
 */
function findStoryMerge(root, sprintBranch, id, tip) {
  const r = git(root, ['log', '--first-parent', '--merges', '--format=%H %P%x09%s', sprintBranch, '--']);
  if (r.status !== 0) return null;
  const subject = `merge(story/${id}):`;
  for (const l of lines(r.stdout)) {
    const tab = l.indexOf('\t');
    if (tab < 0 || !l.slice(tab + 1).startsWith(subject)) continue;
    const [sha, , second] = l.slice(0, tab).split(' ');
    if (tip == null || second === tip) return sha;
  }
  return null;
}
```
4. **`finish` closure.** Add after `const worktree = …` (`:260`). It has to sit there, before step 2, because the preconditions call it:
```js
  // 6 and 7. Teardown and state, shared by a fresh merge and a resumed one (Requirement 3). Anything
  // that fails here happens after the merge landed: name the step and the re-run (Requirement 2).
  const finish = ({ mergeSha, resumed, branchGone = false, postMerge = 'skipped', postTail = [] }) => {
    const rerun = `merge_story.mjs ${id} --sprint ${sprintId}${worktreeArg ? ` --worktree ${worktreeArg}` : ''}`;
    const landedLine = `merge commit ${mergeSha} has landed on ${sprintBranch}; re-run ${rerun} to finish teardown and state`;
    const after = (step, tail) => buildResult({ id, step, exit: MERGE_EXIT.PRECONDITION, tail: [...tail, ...notices, landedLine] });
    let step = 'teardown';
    try {
      log(resumed ? `${storyBranch} already merged (${mergeSha}); teardown and state only` : 'teardown');
      if (fs.existsSync(worktree)) {
        let rm = git(root, ['worktree', 'remove', worktree]);
        if (rm.status !== 0) {
          const entries = parsePorcelainZ(git(worktree, ['status', '--porcelain=v1', '-z', '--untracked-files=all']).stdout);
          const real = entries.filter((e) => !isWorktreeResidue(e));
          if (real.length) return after('teardown', ['worktree holds uncommitted work:', ...real.map((e) => `  ${e.status} ${e.path}`)]);
          for (const e of entries) {
            if (!e.path.includes('/.script-incidents/') || !e.path.endsWith('.json')) continue;
            const src = path.join(worktree, e.path);
            if (!fs.existsSync(src)) continue; // deleted or moved out of the worktree: residue, nothing to copy
            const dest = path.join(sprintDir, '.script-incidents');
            fs.mkdirSync(dest, { recursive: true });
            fs.copyFileSync(src, path.join(dest, path.basename(e.path)));
          }
          rm = git(root, ['worktree', 'remove', '--force', worktree]);
          if (rm.status !== 0) return after('teardown', lines(rm.text));
        }
      } else {
        git(root, ['worktree', 'prune']); // a deleted worktree directory still registered blocks the branch delete
      }
      if (!branchGone) {
        // A resumed run may find the main checkout on another branch; its merge commit proves the tip is merged.
        const bd = git(root, ['branch', resumed ? '-D' : '-d', storyBranch]);
        if (bd.status !== 0) return after('teardown', lines(bd.text));
      }
      step = 'state';
      const up = run('node', [path.join(scriptDir, 'update_state.mjs'), id, 'Done'], { cwd: root, env: { ...env, CLEARGATE_STATE_FILE: stateFile } });
      if (up.status !== 0) return after('state', lines(up.text));
    } catch (err) {
      return after(step, [`unexpected error: ${err.message}`]);
    }
    if (resumed) {
      return buildResult({
        id, step: 'done', exit: MERGE_EXIT.MERGED, post_merge_test: 'skipped',
        tail: [`resumed: ${storyBranch} was already merged into ${sprintBranch}; teardown and state only`],
      });
    }
    return fail('done', MERGE_EXIT.MERGED, postTail, { post_merge_test: postMerge });
  };
```
