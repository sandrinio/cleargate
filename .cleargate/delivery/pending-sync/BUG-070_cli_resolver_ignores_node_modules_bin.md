# BUG-070: The CLI resolver skips `node_modules/.bin`, so a locally-installed project silently runs a different version

> **First-user field report.** Surfaced 2026-09-02 while running ClearGate's full
> lifecycle from a `npm pack` tarball installed into a fresh consumer repo.
> This is a **design gap in [[CR-009]]**, not a regression of it — CR-009's
> three-branch order was built for `npx` and global installs and never
> considered a local project dependency.

### Open Questions

- **Question:** Insert `node_modules/.bin/cleargate` into the resolver chain, or resolve the CLI from the *invoking* binary's own path?
- **Recommended:** **Insert it as branch 2**, after the meta-repo dogfood dist and before `command -v`. Resolving from the invoking binary is more correct in principle but the hooks are spawned by Claude Code, not by the CLI, so there is no invoking binary to inherit from — the hook has only `REPO_ROOT`. A local-install branch is the change that matches how the hooks actually run.
- **Human decision:** Unresolved — replace this entire line with the human's decision.

- **Question:** Should `init` report the branch it actually took, rather than the branch it probed?
- **Recommended:** **Yes.** The misleading success line is what made this take real time to notice. `init` printed "resolved via PATH (global install)" while executing from `node_modules`, so the message actively pointed away from the truth.
- **Human decision:** Unresolved — replace this entire line with the human's decision.

## 1. The Anomaly (Expected vs. Actual)

**Expected Behavior:** a project that adds ClearGate as a local dependency
(`npm install cleargate`, the ordinary way to pin a CLI to a repo) gets hooks and
an `init` that run **that installed copy**, at the version the project pinned.

**Actual Behavior:** `node_modules/.bin/cleargate` is in no branch of the
resolver. The chain is:

1. `${REPO_ROOT}/cleargate-cli/dist/cli.js` — meta-repo dogfood
2. `command -v cleargate` — global install on PATH
3. `npx -y cleargate@<pin>` — registry download

A locally-installed project therefore falls to branch 2 or 3:

- **With any global install present:** every hook silently executes the *global*
  version, ignoring the project's pin. A repo pinning `cleargate@0.26.0` on a
  machine with global `0.20.0` runs `0.20.0`, with no warning anywhere.
- **With no global install:** every hook invocation shells out to `npx` and
  re-resolves from the registry — needs network, and still ignores the copy
  already sitting in `node_modules`.

`init` additionally **misreports** which branch it took. Running
`./node_modules/.bin/cleargate init` prints:

```
[cleargate init] 🟢 cleargate CLI resolved via PATH (global install)
```

naming a binary the user did not invoke.

## 2. Reproduction Protocol

1. `mkdir /tmp/repro && cd /tmp/repro && git init && npm init -y`
2. Ensure a global cleargate exists at a *different* version than the tarball
   under test (`npm ls -g --depth=0 | grep cleargate`).
3. `npm install <path-to>/cleargate-<version>.tgz` — a local install only.
4. `./node_modules/.bin/cleargate init`
5. Observe the line `🟢 cleargate CLI resolved via PATH (global install)` — the
   local binary was invoked; the global was named.
6. `grep -n 'command -v cleargate' .claude/hooks/session-start.sh` → the
   generated hooks resolve the same way, so every hook runs the global build.

## 3. Evidence & Context

Resolver in the CLI (`cleargate-cli/src/commands/init.ts:623-641`):

```ts
if (fs.existsSync(distCliPath)) {
  branch = { cmd: 'node', args: [distCliPath, '--version'] };
  branchLabel = `local dist (${distCliPath})`;
} else {
  const whichResult = spawnSyncFn('which', ['cleargate'], { ... });
  if (whichResult.status === 0) {
    branch = { cmd: 'cleargate', args: ['--version'] };
    branchLabel = 'PATH (global install)';
  } else {
    branch = { cmd: 'npx', args: ['-y', `cleargate@${pinVersion}`, '--version'] };
  }
}
```

The identical order is baked into every shipped hook
(`.claude/hooks/session-start.sh:10-15` in the installed payload):

```bash
if [ -f "${REPO_ROOT}/cleargate-cli/dist/cli.js" ]; then
  CG=(node "${REPO_ROOT}/cleargate-cli/dist/cli.js")
elif command -v cleargate >/dev/null 2>&1; then
  CG=(cleargate)
else
  CG=(npx -y "cleargate@0.25.0")
fi
```

Live reproduction, 2026-09-02:

```
invoked:  /Users/ssuladze/Documents/Dev/cg-lifecycle-20260902/node_modules/cleargate/dist/cli.js
reported: PATH (global install)
which:    /opt/homebrew/bin/cleargate  → /opt/homebrew/lib/node_modules/cleargate (real install, not a link)
```

Two different files. The one that ran was not the one named.
