# STORY-051-01: Restore File-Surface Pre-Commit Gate to Blocking
**Complexity:** L2 — Delete the retired `execution_mode`/v1/v2 code path from `file_surface_diff.sh` so off-surface staged files block unconditionally, leaving `SKIP_SURFACE_GATE=1` as the only bypass; sweep the dead vocabulary from the script and its test; sync all three dogfood copies.

## 1. The Spec (The Contract)

### 1.1 User Story
As a ClearGate maintainer relying on the pre-commit file-surface gate, I want off-surface staged files to fail the commit unconditionally (with `SKIP_SURFACE_GATE=1` as the sole escape hatch), so that the gate that CLAUDE.md and `cleargate-enforcement.md` call "always enforced" actually blocks instead of silently resolving to the retired `v1` advisory branch and manufacturing false assurance.

### 1.2 Detailed Requirements
- Remove the `detect_execution_mode()` function (canonical lines 47–82) and its call site (lines 84–88), including the two `echo "v1"` fallbacks (55, 81), the `grep` of `"execution_mode"` (61, 75), and the `EXECUTION_MODE="v1"` assignment (85).
- Remove the `--v1` / `FORCE_V1` flag entirely: the usage line mention (line 5), the `FORCE_V1=0` declaration (27), the `--v1) FORCE_V1=1` arg-parse case (33), and the `if [[ "${FORCE_V1}" == "1" ]]` branch (84–88).
- Replace the terminal `if [[ "${EXECUTION_MODE}" == "v1" ]] … exit 0 … else … exit 1` block (lines 305–320) with a single unconditional off-surface path: when `off_surface` is non-empty, print each offending file on stderr and `exit 1`; when empty, `exit 0` (already at line 300–302).
- The off-surface report MUST name each offending file (one `off-surface: <path>` line per file on stderr) before the non-zero exit.
- Preserve every existing exit-0 early-return unchanged: `SKIP_SURFACE_GATE=1` bypass (40–43), no active story file (151–154), no declared §3.1 paths (197–200), nothing staged (209–212), all-on-surface (300–302).
- `SKIP_SURFACE_GATE=1` remains the ONLY bypass to a clean exit when off-surface files exist.
- Rewrite the header comment block so the usage line, the `Exit codes` doc (lines 11–13), and every in-body comment contain zero `v1` / `v2` / `execution_mode` / `EXECUTION_MODE` / `FORCE_V1` / `--v1` tokens.
- Update `test_file_surface.sh`: assert unconditional blocking (Scenario 1 no longer depends on a mode), replace the "v1 mode is advisory" scenario (lines 168–198) with a "SKIP_SURFACE_GATE=1 bypasses" scenario (off-surface staged file + `SKIP_SURFACE_GATE=1` ⇒ exit 0), and change `create_sprint_state` so it stops writing the `execution_mode` key into `state.json` (drop the `mode` parameter and the `"execution_mode":"…"` fragment at line 73).
- Sync all three copies of each file byte-identically: canonical (`cleargate-planning/**`) → live (root `.cleargate/**`) → npm payload (`cleargate-cli/templates/cleargate-planning/**`, regenerated by `npm run prebuild`).

### 1.3 Out of Scope
- Changing what counts as on-surface: the §3.1 table parsing (`parse_surface_paths`, lines 158–189) and the `surface-whitelist.txt` format are untouched.
- Adding any `CLEARGATE_ADVISORY=1` soft-bypass path or scenario to this gate (explicitly excluded by the resolved Q1 = narrow; see §1.4).
- Any change to the other enforcement gates (test-ratchet, decomposition/lifecycle-init, `cleargate doctor` drift guard) — those are separate EPIC-051 sibling stories.
- Removing `v1`/`v2`/`execution_mode` vocabulary from any file other than these two — the corpus-wide vocabulary sweep is STORY-051-05, which MUST exclude these two files from its worklist.

### 1.4 Open Questions
> The one decision this story depends on was answered at gate review; recorded below as the Human decision. No new open question surfaced while drafting.
- **Question:** Should `CLEARGATE_ADVISORY=1` also soften the file-surface gate (a second bypass alongside `SKIP_SURFACE_GATE=1`)?
- **Recommended:** Narrow — keep `SKIP_SURFACE_GATE=1` as the file-surface gate's only bypass; do not thread `CLEARGATE_ADVISORY` here.
- **Human decision:** Q1 = NARROW (final, gate review 2026-07-17). `CLEARGATE_ADVISORY=1` softens ONLY `cleargate sprint preflight`, never this gate. Do NOT add a `CLEARGATE_ADVISORY` soft-bypass path or gherkin scenario. `SKIP_SURFACE_GATE=1` is the sole bypass.

### 1.5 Risks
- **Risk:** The gate ships in the npm payload (v0.17.1); a regression that mis-blocks a legitimate on-surface commit reaches every end user's pre-commit hook. / **Mitigation:** the bash test harness asserts all three axes before merge — off-surface blocks (exit 1 + names file), on-surface passes (exit 0), and `SKIP_SURFACE_GATE=1` bypasses (exit 0); QA runs the harness green.
- **Risk:** Shared-file collision with the corpus vocabulary-sweep sibling STORY-051-05 — if both stories edit `file_surface_diff.sh` / `test_file_surface.sh` the commits conflict and the sweep may re-touch tokens this story already removed. / **Mitigation:** this story owns the full v1/v2 removal for these two files; STORY-051-05 MUST list both files on its exclusion list (call this out in the epic's story-ordering note).
- **Risk:** Dogfood-split drift — editing canonical but forgetting the live or payload copy leaves the executing gate stale (this is exactly how CR-074 shipped a fix while running the buggy hook). / **Mitigation:** the §3.1 table enumerates all three copies of both files; DoD requires `diff` between canonical/live/payload to be empty and `npm run prebuild` to regenerate the payload before commit.

### 3.2 Technical Logic
**In `file_surface_diff.sh`:**
1. **Header (lines 1–13).** Drop `[--v1]` from the usage line. 3. **Mode detection (lines 45–88).** Delete the entire `detect_execution_mode() { … }` function (47–82) and the `if [[ "${FORCE_V1}" == "1" ]] … EXECUTION_MODE=…` block (84–88). No `EXECUTION_MODE` variable remains anywhere.

All other early exits (bypass 40–43, no-story 151–154, no-declared-paths 197–200, nothing-staged 209–212) are untouched.

Net behavior: with an off-surface staged file and no bypass, the gate now always reaches `exit 1` and names the file; the only way to a clean exit with off-surface files staged is `SKIP_SURFACE_GATE=1`.

## Why not simpler?
- **Smallest existing surface that could carry this:** `file_surface_diff.sh` itself — this is a net-deletion refactor of one existing script plus its existing bash harness; no new file, function, or config is introduced.
- **Why isn't extension / parameterization / config sufficient?** The bug is precisely that a parameter (`execution_mode`, resolved from `state.json`) still gates enforcement, but the field it reads no longer exists after CR-070/CR-074, so the script always falls through to the `v1` advisory branch and never blocks. Keeping the parameter and "fixing" it would mean re-introducing a retired behavior axis — forbidden by the EPIC-051 architecture rule that `CLEARGATE_ADVISORY=1` is the only sanctioned strength lever. The only correct fix is to delete the parameter and its branch so blocking is unconditional; a config flag or new parameter would recreate the exact class of dead-switch the epic exists to purge.
