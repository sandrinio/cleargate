# BUG-070: The CLI resolver skips `node_modules/.bin`, so a locally-installed project silently runs a different version

**Status:** Triaged · **Sprint:** none · **Gate:** pass · **Severity:** P1-High

## Anomaly
**Expected Behavior:** a project that adds ClearGate as a local dependency
(`npm install cleargate`, the ordinary way to pin a CLI to a repo) gets hooks and
an `init` that run **that installed copy**, at the version the project pinned.

**Actual Behavior:** `node_modules/.bin/cleargate` is in no branch of the
resolver. The chain is:

1. `${REPO_ROOT}/cleargate-cli/dist/cli.js` — meta-repo dogfood
2. `command -v cleargate` — global install on PATH
3. `npx -y cleargate@<pin>` — registry download

## Reproduction
1. `mkdir /tmp/repro && cd /tmp/repro && git init && npm init -y`
2. Ensure a global cleargate exists at a *different* version than the tarball
   under test (`npm ls -g --depth=0 | grep cleargate`).
3. `npm install <path-to>/cleargate-<version>.tgz` — a local install only.
4. `./node_modules/.bin/cleargate init`
5. Observe the line `🟢 cleargate CLI resolved via PATH (global install)` — the
   local binary was invoked; the global was named.
6. `grep -n 'command -v cleargate' .claude/hooks/session-start.sh` → the
   generated hooks resolve the same way, so every hook runs the global build.
