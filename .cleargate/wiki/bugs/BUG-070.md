# BUG-070: The CLI resolver skips `node_modules/.bin`, so a locally-installed project silently runs a different version

> **First-user field report.** Surfaced 2026-09-02 while running ClearGate's full
> lifecycle from a `npm pack` tarball installed into a fresh consumer repo.
> This is a **design gap in [[CR-009]]**, not a regression of it — CR-009's
> three-branch order was built for `npx` and global installs and never
> considered a local project dependency.

### Open Questions

- **Question:** Insert `node_modules/.bin/cleargate` into the resolver chain, or resolve the CLI from the *invoking* binary's own path?
- **Recommended:** **Insert it as branch 2**, after the meta-repo dogfood dist and before `command -v`. Resolving from the invoking binary is more correct in principle but the hooks are spawned by Claude Code, not by the CLI, so there is no invoking binary to inherit from — the hook has only `REPO_ROOT`. A local-install branch is the change that matches how the hooks actually run.
- **Human decision:** Unresolved — replace this entire line with the human's decision.
