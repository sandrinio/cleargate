# CR-099: The Dogfood Split Does Not Match What CLAUDE.md Says It Is

**Status:** Completed · **Sprint:** none · **Gate:** pass

## Context override
**Obsolete Logic (What to Remove / Forget):**
- Forget that `/.claude/**` is uniformly gitignored in the meta-repo. Exactly one file under it is tracked, and `.gitignore` has no effect on already-tracked files.
- Forget that the npm payload is tracked. CLAUDE.md says "**NPM payload (tracked, auto-mirrored):** `cleargate-cli/templates/cleargate-planning/.claude/**`". `git ls-files` returns nothing for that path — it is gitignored in the `cleargate-cli` repo and regenerated by `prebuild`.

**New Logic (The New Truth):**
- `/.claude/**` is uniformly gitignored **and uniformly untracked**. `git ls-files .claude/` returns 0, with no exceptions. Machine-checked, not honour-system.
- The npm payload is a **generated, gitignored build artifact**, regenerated from canonical by `npm run prebuild` and again by `prepublishOnly`. It is never a source of truth and is never hand-edited.
- Canonical (`cleargate-planning/.claude/**`) is the only tracked copy, and remains the only place edits land.

**Why it matters.** The dogfood split has bitten before: CLAUDE.md records that BUG-024 "shipped its own fix while still running with the buggy hook" because canonical was edited and the live instance never re-synced. The same shape recurred in this session — `.claude/hooks/token-ledger.sh` was tracked *and* stale, so the repo was about to ship the `[[CR-097]]` attribution fix while executing the pre-fix hook. It was caught only because `git status` showed the file as modified, which happens for exactly one of the nine live hooks.
